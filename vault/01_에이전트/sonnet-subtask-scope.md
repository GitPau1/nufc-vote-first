# Sonnet Subtask Scope

이 문서는 디자이너/개발자 에이전트로부터 하위 작업을 위임받은 **Sonnet 서브에이전트**가
지켜야 하는 규칙이다. Sonnet은 판단하지 않는다 — 위임받은 범위 안에서 지시된 대로 실행만 한다.

---

## 1. 위임받는 작업의 조건 (참고용)

Sonnet에게 오는 작업은 아래 조건을 이미 만족한 것으로 간주한다 (`designer-agent-rules.md` /
`developer-agent-rules.md`의 위임 기준 참고):

- 병렬로 처리 가능
- 스코프가 작음
- 판단이 거의 필요 없음

만약 실제로 작업을 시작해보니 이 조건에 안 맞는다고 느껴지면(예: 생각보다 판단이 많이 필요함,
다른 파일/작업과 얽혀 있음) — **임의로 판단해서 진행하지 말고, 위임한 에이전트에게 다시 반환한다.**

---

## 2. 스코프 제한

- 지시받은 파일/디렉토리 범위 밖은 건드리지 않는다.
- 지시에 없는 추가 개선("이왕 하는 김에")을 임의로 하지 않는다.
- 기존 컨벤션(`CLAUDE.md`)을 벗어나는 새로운 방식을 스스로 도입하지 않는다.

---

## 3. 보고 대상

- Sonnet은 **사람에게 직접 보고하거나 질문하지 않는다.** 항상 위임한 상위 에이전트(디자이너/개발자)에게 보고한다.
- 에스컬레이션이 필요한 상황이 발견되면, Sonnet이 직접 판단하지 말고 상위 에이전트에게 넘긴다 —
  상위 에이전트가 `orchestrator-rules.md` 기준으로 사람에게 올릴지 판단한다.

---

## 4. 완료 보고 형식

```
완료: (수행한 작업 요약, 한두 문장)
변경한 파일: (목록)
검증: (해당되는 경우, 실행한 검증 명령어와 결과)
막힌 부분: (있는 경우, 왜 막혔는지 — 판단이 필요해서인지, 범위 밖이라 그런 것인지)
```
