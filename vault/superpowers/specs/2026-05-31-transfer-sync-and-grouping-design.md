# 이적 동기화 및 분류 보정 설계서

## 1. 목표

- 선수 대시보드에서 `구단 외 선수`와 `임대 선수`를 숨긴다.
- 관리자 이적 탭과 공개 `/transfers` 페이지가 같은 transfer 데이터를 기준으로 갱신되도록 맞춘다.
- 이적 목록을 `임대`와 `영구 이적`으로 분리해 보여준다.

## 2. 문제 인식

현재 구조에는 두 가지 불일치가 있다.

- 선수 대시보드가 `구단 내 선수`를 보여주는 화면이어야 하는데, `구단 외 선수`와 `임대 선수`가 섞여 보일 수 있다.
- 이적 관련 데이터는 `farewell`과 `transfers`가 역할을 나눠 가진 상태인데, 관리자 이적 탭은 아직 farewell 중심이고 공개 `/transfers`는 transfers 중심이라서 목록 갱신 기준이 다르다.

이 상태에서는 같은 동작을 해도 한 화면은 바뀌고 다른 화면은 안 바뀌는 문제가 발생한다.

## 3. 합의된 표시 규칙

### 선수 대시보드

- 선수 대시보드의 `선수` 섹션은 `실제 현재 구단 내에서 뛰는 선수`만 보여준다.
- 따라서 다음 두 그룹은 숨긴다.
  - `구단 외 선수`
  - `임대 선수`

표시 기준:

- 보여줌: `is_active === true` 이고 `squad_status !== 'loan'`
- 숨김: `is_active === false`
- 숨김: `squad_status === 'loan'`

### 이적 목록

- 관리자 이적 탭과 공개 `/transfers` 페이지 모두 같은 분류 규칙을 사용한다.
- 두 화면 모두 `영구 이적`과 `임대`를 분리해 섹션으로 보여준다.

## 4. 분류 기준

### 임대

- `loan_in`
- `loan_out`

### 영구 이적

- `signing`
- `promotion`
- `transferred`
- `contract_expired`
- `released`

현재 범위에서는 이 기준이면 충분하다.
별도 DB 컬럼을 추가하지 않고 `transfer_type`만으로 분류한다.

## 5. 데이터 책임 정리

### farewell

- farewell은 계속 `작별 콘텐츠` 역할을 맡는다.
- 작별 상세 페이지, 작별 메시지, 댓글, 떠난 선수 기록 편집 같은 흐름은 farewell이 담당한다.

### transfers

- transfers는 `이적 목록` 역할을 맡는다.
- 관리자 이적 탭과 공개 `/transfers` 페이지는 transfers를 기준으로 읽는다.
- 두 화면은 farewell이 아니라 transfers의 현재 시즌 데이터와 분류 결과를 사용해야 한다.

## 6. 동기화 문제의 원인과 보정 방향

### 현재 의심 원인

- `Out` 등록 시 farewell은 생성되지만 transfers까지 항상 일관되게 반영되지 않을 수 있다.
- 관리자 이적 탭은 farewell 목록을 보여주고 있어서, transfers가 업데이트돼도 화면이 즉시 반영되지 않는다.
- 공개 `/transfers`는 transfers만 보고 있어서, 관리자 쪽과 표시 대상이 어긋난다.

### 보정 방향

- 관리자 이적 탭도 transfers 기준 목록을 사용하도록 바꾼다.
- farewell 수정/복귀 액션은 콘텐츠/작별 쪽 책임을 유지하되, 목록 표시 자체는 transfers 기준으로 읽는다.
- `Out` 생성, `In` 생성, 복귀 처리 후에는 `/admin`과 `/transfers`가 같은 transfer query를 다시 읽도록 맞춘다.

## 7. 구현 원칙

### 선수 대시보드

- `AdminDashboard`의 선수 목록 렌더링에서 `internalPlayers`를 다시 정의한다.
- `internalPlayers`는 `is_active === true && squad_status !== 'loan'` 조건만 포함한다.
- `externalPlayers`와 `loan` 그룹은 선수 대시보드 메인 노출에서 제외한다.

### 이적 목록 조회

- transfers query에서 `transfer_type` 기반 분류값을 만들거나, 화면 진입 직전에 동일한 helper로 분류한다.
- 추천은 query 또는 공용 helper에 분류 함수를 두고 관리자/공개 화면이 같이 쓰는 방식이다.

### 관리자 이적 탭

- 기존 farewell 목록 중심 패널을 transfer 목록 중심 패널로 바꾼다.
- 섹션은 다음 순서로 둔다.
  - 영구 이적
  - 임대

### 공개 `/transfers`

- 현재 시즌 transfer 목록을 불러온 뒤 같은 기준으로 두 섹션으로 나눈다.
- 기존 1열 full-width 카드 구조는 유지한다.

## 8. 검증 기준

- 선수 대시보드에서 `구단 외 선수`와 `임대 선수`가 보이지 않아야 한다.
- `Out` 등록 후 관리자 이적 탭과 공개 `/transfers`에 모두 반영되어야 한다.
- `In` 등록 후 관리자 이적 탭과 공개 `/transfers`에 모두 반영되어야 한다.
- 복귀 처리 후 `단순 복귀`이면 transfer 목록에 새 항목이 없어야 한다.
- 복귀 처리 후 `단순 복귀`가 아니면 transfer 목록에 새 `In` 항목이 생겨야 한다.
- 관리자 이적 탭과 공개 `/transfers`에서 `임대`와 `영구 이적` 섹션 구성이 같아야 한다.

## 9. 범위 제한

- 이번 작업에서는 farewell 상세 페이지의 디자인이나 댓글 구조는 바꾸지 않는다.
- 이번 작업에서는 transfer 스키마를 추가 확장하지 않는다.
- 이번 작업에서는 시즌 필터를 다시 여러 개로 늘리지 않는다.
