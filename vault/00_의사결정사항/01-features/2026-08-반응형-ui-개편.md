# Feature Brief: 반응형 UI 개편

## 왜
기존 서비스는 모바일 화면만 있는 상태이고, 모바일 UI 자체도 개편이 필요하다고 판단했다.
(개편이 필요한 구체적 근거·지표는 회의록에 명시되어 있지 않음 — 다음 회의에서 확인 필요.)

## 무엇
- 모바일 UI 개편
- 데스크탑 화면을 새로 만들어 **반응형**으로 대응

## 어떻게 (기술 방향)
프론트엔드·백엔드는 기존 환경을 그대로 유지한 상태에서 UI만 개편한다 ([[../02-adr/001-기존-vercel-supabase-환경-유지]]).

작업 프로세스(부건):
핵심기능 정의 → 사용자 플로우 작성 → Lofi 화면 작성 → AI 활용 사용자 테스트 → 디자인 소스 활용해 HTML 생성

최종 산출물은 **HTML**을 목표로 한다.

작업 프로세스(수빈):
Supabase 개편 작업 선행 → 프론트 시안 나오면 그 시안으로 작업 수행

## 디자인 방향
데스크탑 화면은 신규 작성이며, 모바일과 함께 반응형으로 묶는다. 그 외 구체적 디자인 방향(레이아웃, 컴포넌트 기준 등)은 Lofi 단계에서 정한다 — 현재 회의록에 명시 없음.

## 범위 밖
- 프론트/백엔드 영역 분리, AWS 이전 (→ [[../02-adr/001-기존-vercel-supabase-환경-유지]])
- 차후 추가로 나오는 작업사항은 이 브리프에서 미리 정의하지 않고, 개발하면서 반영한다.

## 완료 기준
- 핵심기능 정의 완료 (2026-08-19 내)
- 원페이저 제출 (각자 작성)
- AI 활용 사용자 테스트 통과 후 디자인 소스 기반 HTML 산출
