# 사용성 테스트 프로토콜: 1단계 가벼운 사용자 테스트

이 문서는 [[리텐션-개선-원페이저]]의 "개선 전후 비교 방법론" 1단계(가벼운 사용자 테스트 → 개선 사이클)를 실행하기 위한 세부 프로토콜이다. 세션 진행 순서, 질문 문구, 기록 방식, 이슈 판정 기준을 다룬다.

## 기존 지표 재검토

원페이저 초안에는 1단계 지표로 투표 제출 완료율·시작→제출 소요시간·결과화면 체류시간·참여 의향 자기보고(1~5점)를 뒀다. 5~8명 규모 모더레이티드 테스트에는 다음 이유로 이 지표들이 잘 맞지 않는다.

- **제출 완료율**: 모더레이티드 테스트는 참가자가 막히면 진행자가 개입하는 구조라 완료율 자체가 왜곡되며, n=5~8에서는 1명 차이가 곧 10%p 이상 차이로 나타나 비교 근거로 쓰기 어렵다.
- **시작→제출 소요시간**: think-aloud(생각을 말하며 진행)를 적용하면 그 자체로 시간이 늘어나고, 비교할 베이스라인이 없어 값의 빠르고 느림을 판단할 기준이 없다.
- **결과화면 체류시간**: 체류시간이 긴 것이 몰입인지 혼란인지 시간값만으로는 구분되지 않는다.
- **참여 의향 자기보고(1~5점)**: 자기보고 의향과 실제 재방문 행동 사이의 괴리(say-do gap)가 알려져 있어, 소수 표본에서 절대값으로 해석하기 어렵다.

## 1단계의 목적 재정의

- **A. 방향성 검증**: 승부예측·포지션별 MVP 픽·랭킹이 원페이저가 정의한 원인(체감 가치 부족)을 실제로 완화하는 방향인지 확인한다.
- **B. UX/UI 이슈 발견**: A가 맞다는 전제 아래, 플로우 상에서 막히거나 오해가 생기는 지점을 찾는다.

## 편향 차단 장치

| 편향 유형 | 발생 상황 | 차단 장치 |
| --- | --- | --- |
| 순서 효과 | 항상 같은 순서로 화면을 보여주면 나중에 본 화면 쪽에 호감이 실리는 최신 효과가 섞임 | 참가자 절반은 기존→개선안, 나머지 절반은 개선안→기존 순서로 배정 |
| 유도 질문 | 질문 문구에 원하는 답이 암시됨 | 질문지를 세션 전 고정 문구로 작성하고, 진행자는 그 문구를 그대로 사용 |
| 사회적 바람직성 | 참가자가 진행자를 배려해 "둘 다 좋다"로 답함 | 비교 질문은 양자택일 강제(중립 옵션 없음) + 이유를 이어서 질문 |
| 자기평가 과신 | "이해되셨나요?"라고 물으면 대부분 긍정으로 답함 | 이해 여부를 직접 묻지 않고 본인 말로 설명해달라고 요청해 행동으로 확인 |
| 진행자의 사후 인상 | 세션 중 형성된 인상이 관찰 기록에 그대로 섞임 | 세션 중에는 사실(행동·발화)만 기록하고, 해석·심각도 태깅은 세션과 분리된 별도 단계에서 수행 |

## 세션 진행 시나리오 (참가자 1인당 약 40분)

**0. 인트로 (5분)** — 모든 참가자에게 동일한 문구를 그대로 읽는다.

> "오늘은 화면 두 개를 차례로 사용해보실 거예요. 정답은 없고, 편하게 생각나는 대로 말씀하면서 진행해주시면 됩니다."

참가자 배경(뉴캐슬 팬 강도, 기존 서비스 이용 경험 유무)은 별도 속성 항목으로만 기록하고 이후 해석에 바로 반영하지 않는다.

**1. 과제 수행 A (10분, think-aloud)**

표준 과제 문구: *"이번 주 뉴캐슬 경기 결과를 예측해서 투표를 제출해보세요."*

진행자는 원칙적으로 침묵 관찰한다. 참가자가 5초 이상 멈추면 다음 문구만 사용한다: *"지금 어떤 생각을 하고 계신가요?"* (답을 암시하지 않는 개방형 질문만 허용)

기록은 사실과 해석을 분리한 2열 시트에 남긴다.

| 시각 | 사실(관찰) | 해석(가설, 별도 표시) |
| --- | --- | --- |
| 3:20 | 배당 안내 문구에서 마우스 정지 8초 | (가설) 배당 개념이 바로 이해되지 않았을 가능성 |
| 4:05 | "이게 뭐지?" 발화, 뒤로가기 클릭 | (가설) 화면 전환 흐름 혼란 |

해석 칸은 그 자리의 추측이며, 3단계 질문이나 참가자 발화로 확인되지 않으면 최종 이슈 목록에 넣지 않는다.

**2. 과제 수행 B (10분)** — 동일 과제, 동일 방식으로 대상 화면을 바꿔 반복한다.

**3. 비교 질문 (10분, 질문지 고정, 순서와 무관하게 모든 참가자에게 동일 문구 사용)**

1. *"방금 보신 두 화면 중, 다음 경기에도 다시 쓰고 싶은 쪽은 어느 쪽인가요?"* (양자택일 강제)
2. *"그렇게 고르신 이유가 뭔가요?"* — 발화를 요약·의역 없이 그대로 기록
3. *"이 기능이 있으면 다음 주에 앱을 다시 켤 것 같나요? 왜 그렇게 생각하세요?"*
4. *"방금 보신 화면에서 점수는 어떻게 매겨지는지, 본인 말로 설명해주실 수 있나요?"* (이해 여부를 직접 묻지 않고 설명을 요청해 확인)

**4. 세션 종료 후 코딩 (참가자 없이, 세션과 분리된 단계)**

녹화본을 다시 보며 1~2단계에서 남긴 "가설" 표시를 3단계의 실제 발화와 대조해 확인하거나 기각한다. 확인된 이슈만 아래 루브릭으로 심각도를 태깅한다.

## 심각도 루브릭 (사전 정의, 태깅 시 이 기준만 적용)

| 등급 | 기준 |
| --- | --- |
| Critical | 과제를 완료하지 못했거나, 재방문 의향 질문(3-3번)에서 해당 이슈를 이유로 "안 올 것 같다"고 명시적으로 답함 |
| Major | 완료는 했으나 개방형 유도 질문이 필요했거나, 3-4번 설명 요청에서 채점 방식을 틀리게 설명함 |
| Minor | 불편함을 언급했으나 과제 완료나 재방문 의향에 영향을 준 근거가 발화에 없음 |

가능하면 진행자 외 1명이 같은 녹화본을 독립적으로 태깅한 뒤 불일치 지점만 논의한다. 인원상 어려우면, 최소한 "루브릭 문구대로만 태깅했는지"를 다른 사람이 사후 재검토하는 것으로 대체한다.

## 산출물 형태

- 참가자별 원문 인용 목록 (요약 없이 그대로)
- 이슈 목록 (등급 + 발생 화면 + 근거가 된 인용)
- 비교 선택 결과: "N명 중 M명이 개선안 선택" + 각자의 이유 인용 나열. n=5~8에서는 퍼센트 환산이 과대해석을 유발할 수 있어 "몇 명 중 몇 명" 원 표기를 유지한다
- 소요시간·체류시간은 목표치 없는 참고 관찰 메모로만 남기고, 성공 기준에는 포함하지 않는다

## 남은 미확정 사항

- 참가자 모집 기준(뉴캐슬 팬 강도, 기존 서비스 이용 경험 유무의 구성 비율)
- 세션 수 및 이슈 발견 시 재테스트 라운드 진행 조건
- 독립 코더 확보 가능 여부
