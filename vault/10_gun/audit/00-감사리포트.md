## ⚠️ 먼저 — 계획서 전제 중 실측으로 낡은 것으로 확인된 부분

조사 결과, 계획서가 쓰일 당시의 전제 몇 개가 현재 코드와 어긋난다. **이건 계획서를 부정하는 게 아니라, 계획서가 명령한 "근거는 실재 코드"라는 원칙을 그대로 적용한 결과다.**

1. **[1-C] 계획서가 "확정 위반"으로 지목한 3개 파일(`admin/ratings`, `AdminRatingsForm`, `NavigationLoading`)은 이미 semantic 토큰으로 이관 완료.** 구세대 토큰(`bg-primary`/`text-gray-2`/`border-gray-4`) **0건**. `design-foundation.test.mjs:383` 주석의 전제가 stale이다. → Wave B의 "3개 파일 이관"은 사실상 불필요.
2. **[1-C] 대신 test가 못 잡는 진짜 잔여를 새로 발견: 죽은 클래스 `divide-border`(8건)·`ring-border`(2건).** 폐기된 `border` 색 토큰을 참조해 조용히 무효화된 상태(구분선·링이 안 보임). 이게 이번에 새로 드러난 실질 위반이다.
3. **[1-A] tier 초안 분류에 오류 3건.** `StickyActionBar`는 조합체(2-a)가 아니라 순수 `children` 래퍼 → Tier 1. `PollPageHeader`는 화면 클라이언트가 아니라 7곳 재사용 어댑터 → 2-a. `AdminRatingsForm`은 어느 목록에도 없던 항목 → 2-b. 그리고 계획서가 2-a로 든 8개는 "현재 사용처 1곳"(재사용 설계일 뿐 다중 사용 아님).
4. **[1-D] PlayerPickModal의 shell 격리 명분("ui/sheet는 하단 고정이라 반응형 불가")은 낡음.** `bottom-sheet.tsx:57`이 바로 그 반응형(모바일 하단↔데스크탑 중앙) 전환을 이미 한다. → shell 통합 가능.

## 섹션별 요약

### 1-A. 컴포넌트 tier + 폴더 구조 → [상세](1-A-tier-and-folders.md)
- 컴포넌트 **53개 전수**를 Tier 1(원자, 12) / 2-a(재사용 조합, 22) / 2-b(화면 조립, 16) / 비-UI(3)로 분류. 합계 검증 완료.
- 핵심 방법론 정정: **"import 안 함(leaf) ≠ Tier 1"** — leaf지만 도메인 카드/부수효과인 것 다수. tier는 "성격 축"으로 판정.
- 폴더 구조 2안 트레이드오프 제시(안 A: 53개 이동·테스트 41개 경로 재작성 / 안 B: 이동 0·리스크 0). → **D1**.

### 1-B. 문서 이력·군더더기 → [상세](1-B-doc-history.md)
- `storybook/**/*.mdx` 49개 + `DESIGN-SYSTEM.md` 전수 스캔. 파일별로 [삭제]/[각주 이동]/[유지] 태깅(요약표 존재).
- 삭제/이동 대상은 거의 전부 **"본문 안 특정 절(clause)"** — 문단 통째 삭제는 없음. 규칙과 경위가 한 문장에 붙어 있어 절 단위로 갈라야 함.
- `deleteUserPoll` 보안 근거·3대 불변식·의도적 미사용 등 **판단 근거 서술은 [유지]**로 정확히 보존(계획서 지시 준수).
- **핵심 확인**: `retired legacy color class names` 검사(mdx도 스캔)와 충돌 없음 — 태깅된 삭제/이동 대상 중 폐기 클래스명을 인용하는 문장은 없음. 예외 파일 `DesignToken.mdx`는 손대지 않는 게 안전. → **D6, D7**.

### 1-C. foundation 준수 → [상세](1-C-foundation-compliance.md)
- **총평: color/typography 준수 매우 양호.** 진짜 구세대 색 토큰(primary/gray/*-dim/negative)은 리포 전체 0건.
- 계획서 지목 3개 파일 = 이미 이관 완료(위 ⚠️2). 대신 **죽은 클래스 `divide-border`×8·`ring-border`×2** 발견 → 청소 + renamed 맵에 키 추가로 재유입 차단.
- 정당한 예외 3건(구글 로고 hex·`--c-black` 스크림·Sheet 미사용 export) 코드 근거로 재확인. → **D2, D3**.

### 1-D. 단일 shell 원칙 → [상세](1-D-single-shell.md)
- **`ui/bottom-sheet.tsx`를 정식 단일 shell로 확정 타당** — 모바일 하단↔데스크탑 중앙 반응형·오버레이·드래그핸들·포커스트랩·ESC 전부 구비.
- 모달/시트 표면 6개 전수: 준수 3(Login/Confirm/RequireAuth), **우회 2**(PlayerPickModal / UserPollCreateForm의 PlayerPickerSheet), 대상 밖 1(UserMenu=팝오버).
- PlayerPickModal은 [shell로 통합 가능](격리 명분 낡음). 이관 시 (1)스크롤 `className` 주입 필요, (3)선택 UX·(4)접근성 무손실, (2)모션·X버튼은 디자인 변경.
- 부수 발견: `BottomSheet.mdx`가 `center` variant 실사용을 누락(문서 drift) → Wave C 문서화 시 정정. → **D4, D5**.

## 승인 후 실행 순서 (수정판 — 근거 기반)

계획서 Wave A→D 순서 유지. 단 위 실측 반영:

- **Wave A (문서 이력 제거)**: 1-B 태깅대로. `DesignToken.mdx`는 제외(예외 파일). D6·D7 결정 반영.
- **Wave B (foundation 잔여)**: 계획서의 "3개 파일 이관"은 불필요(이미 됨). 대신 **죽은 클래스 청소**(`divide-border`→`divide-neutral-weak` ×8, `ring-border`→D3결정 ×2) + renamed 맵에 두 키 추가 + predict 검사 승격은 **D2 경로대로**. test 383줄 stale 주석 갱신.
- **Wave C (단일 shell)**: `BottomSheet.mdx`에 단일 shell 원칙 명문화(+center variant drift 정정). PlayerPickModal shell 통합(D4 결정 반영). PlayerPickerSheet는 D5 결정 반영.
- **Wave D (폴더 재구성)**: **D1이 안 A/하이브리드일 때만.** 안 B면 Wave A에 흡수되어 불필요.
- 각 웨이브 종료 시 `cd frontend && npm test`(94개 전부) + `npm run lint` 통과 후 개별 커밋(한 줄, main 직접).
