# 디자인시스템 전면 재편 — 확정안 & 실행 계획

> 목적: 컴포넌트를 **폴더로 물리 재편** + **Modal 껍데기↔내용 분리** + 스토리북·문서 재편.
> 분류 기준·폴더 이름·도메인 배치는 **전부 사용자가 결정**(에이전트가 카테고리를 발명하지 않음).
> 근거 데이터: [1-A tier 분류](audit/1-A-tier-and-folders.md)(53개 전수).

## 실행 대원칙 (사용자 지정)

**실행 중 계획에 명시되지 않은 해석·결정이 필요해지면, 임의로 진행하지 않고 반드시 멈추고 사용자에게 확인한 뒤 진행한다.** 폴더·이름·배치·동작 어느 것이든 "이 정도는 이렇게 하면 되겠지"로 넘기지 않는다. [[dont-invent-structure]]

---

## 1. 분류 기준 (사용자 확정 — 2단계)

컴포넌트는 딱 **2단계**로만 나눈다.

1. **`primitives/`** — 원자 단위. 재사용 최소단위. **Modal도 여기(primitives/modal/)에 들어간다.**
2. **`composition/`** — 조합체(+일회성 화면). 안에 **도메인별 폴더**를 둔다. 특정 도메인에 안 묶이는 조합체는 **`composition/common/`**.

> layout·patterns·features 같은 별도 버킷은 두지 않는다(이전 시안에서 에이전트가 임의로 만든 것 — 폐기).
> 폴더는 리포 관례대로 소문자(`primitives/`, `composition/`, `common/` …).

## 3. Modal 설계

### 껍데기 `primitives/modal/Modal.tsx`
```tsx
type ModalPresentation = 'responsive' | 'default' | 'sheet'
interface ModalProps {
  open: boolean
  onOpenChange: (open: boolean) => void
  presentation?: ModalPresentation   // 기본 'responsive'
  className?: string                  // 목록형은 max-h/overflow 주입
  children: React.ReactNode          // ← 내용(contents/*)
}
```
- **상태 2개**: `default`(중앙 모달) / `sheet`(바텀시트).
- `presentation`:
  - `'responsive'`(기본) = 데스크탑 default / 모바일 sheet
  - `'default'` = 항상 중앙 (로그인 등 모바일에서도 default 강제)
  - `'sheet'` = 항상 바텀시트
- 껍데기 전담: 오버레이 · 위치/폭/반응형 · 드래그 핸들(sheet) · 포커스 트랩·ESC · 우측 상단 X.
- 내부는 현 `sheet.tsx`의 `center`(=default)/`bottom`(=sheet) variant 재사용.

### 내용 `primitives/modal/contents/*`
- 각 모달의 **본문만**(제목·설명·본문·버튼). 자기 props만 받고 열림상태·껍데기는 모른다.
- 파일 상단 주석에 **사용 도메인** 기록(예: `// 사용 도메인: auth`).
- **호출부에서 껍데기+내용을 직접 조립**(사용자 예시 "LoginModal → Modal + Modal/Login"에 맞춰 편의 래퍼는 없앰):
```tsx
<Modal open={open} onOpenChange={setOpen} presentation="default">
  <LoginContent triggerAction="vote" />
</Modal>
```
- 조립 교체 대상 호출부: LoginModal(7곳) · ConfirmModal(3곳) · PlayerPickModal(1곳) · PollPicker(1곳). open 상태는 지금 이미 호출부가 들고 있으므로 그대로 둔다.

## 4. 실행 계획 (단계별 — 각 단계 test/lint/tsc green 후 커밋)

**Phase 1 — Modal 분리**
- `primitives/modal/` 생성: `bottom-sheet.tsx`→`Modal.tsx`(presentation prop 추가), `sheet.tsx` 이동, 각 모달 내용을 `contents/*`로 추출(도메인 주석).
- 호출부를 `<Modal><XContent/></Modal>` 조립으로 교체.
- `RequireAuthModal`은 내부에서 이 조립을 하도록 갱신(auth 게이트 유지).
- 검증: `npm test`(149) + `lint` + `tsc`. → 커밋.

**Phase 2 — primitives/ 이동**
- `git mv` ui/* → primitives/*, layout/{StickyActionBar,PageContainer,NavigationLoading} → primitives/*.
- import 경로 일괄 갱신: `@/components/ui/button` → `@/components/primitives/button` 등, 이동 파일의 상대 import.
- **테스트 하드코딩 경로 갱신**: `design-foundation.test.mjs`(파일 목록·PREDICT_FILES), `navigation-loading.test.mjs`, `header-auth`·`middleware-auth` 등 — 실행 시 `grep -rn "components/" *.test.mjs`로 전수 확인.
- 검증 → 커밋.

**Phase 3 — composition/common/ 이동**
- `git mv` layout 네비/헤더 6개 + HomeClient + AppAnalytics + CroppedImageInput → composition/common/.
- import·테스트 경로 갱신. 검증 → 커밋.

**Phase 4 — composition/<도메인>/ 이동**
- polls·predict·players·auth·my·admin 각 도메인 폴더로 `git mv`.
- import·테스트 경로 갱신(특히 design-foundation의 PREDICT_FILES 경로, poll-list-client·prefetch-policy 등). 도메인 단위로 나눠 커밋.
- 검증(각 도메인 이동 후 `npm test`).

**Phase 5 — 스토리북·문서**
- `.stories.tsx`의 `title`(예: `Primitives/Modal`, `Composition/Polls/PollCard`)·import 경로, `.mdx`의 import·상호 링크 경로 갱신.
- `DESIGN-SYSTEM.md` 표를 새 경로로 재작성(tier 열은 primitives/composition 구분으로 대체 가능).
- `contents/*` 사용 도메인을 문서에 기록.
- `npm run build-storybook`로 전 스토리·MDX 해석 확인. → 커밋.

**최종 검증:** `npm test` + `lint` + `tsc` + `npm run build` + `build-storybook` 전부 green.
