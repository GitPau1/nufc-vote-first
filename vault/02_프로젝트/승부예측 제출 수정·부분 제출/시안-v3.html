승부예측 제출 수정·부분 제출 — 화면 시안 v3 (실제 컴포넌트 마크업 기반 와이어프레임)

v1·v2는 CSS 변수를 새로 만들어 시각적으로 "비슷하게" 그린 목업이었습니다. 이번 v3은 방식을 바꿨습니다 — frontend/src/components/composition/predict/PredictionFlowClient.tsx, PredictionMatchSelect.tsx, steps.tsx, components/primitives/card.tsx, components/primitives/button.tsx를 먼저 읽고 그 안의 실제 Tailwind 클래스 문자열을 그대로 복사해서 조립했습니다. 각 프레임은 독립된 <iframe>에 실제 프로젝트와 같은 Tailwind 설정(tailwind.config.ts) + 같은 디자인 토큰(globals.css의 --sem-*)을 그대로 로드해서 렌더링합니다 — 화면을 인터넷 연결 상태에서 열어야 정상적으로 보입니다(Tailwind CDN 스크립트를 불러옵니다).

이번에 고치는 것 3가지 (사용자 지적): ① 경기 선택 화면이 PredictionFlowClient의 실제 헤더(제목 좌측+진행 pill 우측)·Card· Button 패턴과 안 맞음 → 재사용하도록 다시 그림. ② 데스크톱에서 경기 카드가 세로 스택 → 가로 배열로, "둘 다 예측하기" 버튼 배치도 재조정. ③ 더블 매치위크 "둘 다 예측하기"를 기존 합쳐진 화면(isMulti 분기 + 경기별 BudgetBar 스택 + "그대로 적용") 대신 싱글 매치 플로우를 경기 1 → 경기 2 순서로 두 번 타는 방식(오케스트레이터 제안, 사용자 확인 대기 중)으로 바꿨을 때의 화면.

1. 경기 선택 화면 (제출 문맥) — PredictionMatchSelect 재설계

기존 코드(PredictionMatchSelect.tsx)는 카드가 border border-neutral-weak bg-surface p-4인 독자적 흰 박스였고 헤더가 가운데 정렬(text-center)이었습니다. PredictionFlowClient가 실제로 쓰는 패턴 — 바깥은 Card(rounded-lg border-neutral-weak bg-surface shadow-g200) 하나, 안쪽 좌측정렬 헤더(text-heading-2 font-semibold + text-label-2 text-neutral-muted), 안쪽 서브패널은 SummarySection처럼 bg-page(흰 카드 안 옅은 회색, 이중 테두리 아님) — 으로 바꿨습니다. 경기 카드 컨테이너에 sm:flex-row sm:gap-4를 추가해 데스크톱에서 가로 배열되고, 각 카드는 sm:flex-1로 균등폭입니다. 버튼은 components/primitives/button.tsx의 buttonVariants 클래스(기본/아웃라인)를 그대로 복사해 썼습니다. 아래 두 프레임은 같은 HTML입니다 — iframe 폭만 다르고, 실제 앱과 똑같이 Tailwind의 sm:(640px) 브레이크포인트가 각 iframe 안에서 독립적으로 적용됩니다.

2. 경기 선택 화면 (수정 문맥) — 동일 구조, "둘 다" 버튼 없음

같은 컴포넌트를 mode="edit"로 렌더한 상태입니다. 각 카드 안에 기존 코드가 이미 갖고 있던 "현재 예측 X – Y" 줄(existing 표시, PredictionMatchSelect.tsx:93-97)을 그대로 유지했습니다 — 뭘 고치는지 헷갈리지 않게 하는 정보라 재설계 대상이 아닙니다. "둘 다 수정하기" 버튼은 없습니다 (design-brief §9 질문3=B — 수정은 항상 경기 하나 단위, 기존 결정 유지).

3. 더블 매치위크 "둘 다 예측하기" — 순차(싱글 매치 ×2) 흐름

오케스트레이터 제안(사용자 확인 대기 중): 기존처럼 두 경기를 한 화면에 쌓지 않고, 싱글 매치 스코어→픽→확인 플로우를 경기 1 제출 완료 → 경기 2로 자동 전환 → 경기 2 제출 순서로 두 번 태웁니다. 이 안을 채택하면 PredictionFlowClient.tsx의 isMulti 분기 전체(경기별 MatchLabel, 픽 단계 경기별 BudgetBar 스택, "그대로 적용" copyPicks)가 자연히 필요 없어집니다 — 화면에 항상 경기 하나만 있기 때문입니다.

경기 1(울브스전) 스코어→픽→확인 3단계는 기존 싱글 매치 확인 화면과 완전히 동일합니다 (Card 헤더 "제출 전 확인"+ProgressPips 3/3, SummarySection ×2 — 결과 예측·선수 예측, 하단 이전/제출하기). 반복이라 여기서는 다시 그리지 않고, "제출하기"를 눌러 성공한 직후 무슨 일이 일어나는지(아래 전환 프레임)에 집중했습니다.

↓ "제출하기" 클릭 → 울브스전 제출 성공 → 경기 2(아스널전) 스코어 입력 화면으로 자동 전환

전환 직후 — 아스널전 스코어 입력 (375px)

상단 초록 배너는 신규 제안 UI입니다(기존 코드에 없음) — "지금 뭐가 바뀌었는지" 안내 없이 화면만 바뀌면 사용자가 "왜 갑자기 아스널전이 나오지" 헷갈릴 수 있어 넣었습니다. 이 배너 자체를 넣을지 여부, 넣는다면 문구가 무엇인지 둘 다 미확정입니다.

신규 카피/UI 제안 — 전환 배너 (이번에 처음 필요해진 것, 완전 미확정)

시안 "울브스전 제출 완료 · 이어서 아스널전을 예측해주세요" (초록 배너, 5초 후 자동으로 사라지는 것도 고려 가능)
대안1 배너 없이 화면 상단에 작은 토스트만 잠깐 띄우고 사라짐(현재 상태처럼 계속 보이지 않음)
대안2 안내 자체를 생략 — 헤더의 "경기 예측" 제목과 팀 로고가 바뀌는 것만으로 충분하다고 보고 아무 배너도 없음

확인 필요 — 코디네이터가 전달한 미확정 항목 2가지 (이 와이어프레임엔 반영했지만 최종 결정 아님)

1. "그대로 적용"(픽 복사) 기능 삭제 여부 — 순차 흐름을 채택하면 화면에 경기가 항상 하나뿐이라 이 기능이 설 자리가 자연히 없어집니다. 하지만 "두 경기에 같은 선수를 픽하고 싶은 사용자"에게는 편의 기능이 사라지는 셈이라, 순차 흐름 자체를 채택할지와 별개로 확인이 필요합니다.
2. 경기마다 따로 제출(순차) vs 기존처럼 한 번에 묶어 제출 — 지금 서버 액션 (submitWeekPrediction(weekKey, matchIds, input), lib/actions/predictions.ts)은 이미 경기 단위로 좁혀 받을 수 있어 순차 제출이 기술적으로 자연스럽지만, "두 경기를 한 세트로 묶어 한 번에 제출"이라는 기존 감각을 유지하고 싶다면 다른 처리(예: 경기 2 확인 단계에서 실제로는 두 건을 순서대로 보내되 사용자에게는 "제출 중" 한 번으로 보이게)가 필요할 수 있습니다.
