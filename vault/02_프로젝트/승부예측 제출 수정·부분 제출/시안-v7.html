1·2. 경기 선택 화면 (제출/수정 문맥)

v3와 동일, 변경 없음 — 시안-v3.html의 "1. 경기 선택 화면(제출 문맥)"·"2. 경기 선택 화면(수정 문맥)" 섹션을 그대로 참고하세요. "둘 다 예측하기"를 고르면 아래 3번 섹션의 고정 순서로 들어갑니다.

3. 더블 매치위크 "둘 다 예측하기" — 고정 순서 a-b-a-b-c

새 진행 순서 (자유 전환 아님, 되돌아가기만 가능)

a 경기 1(울브스전) 스코어 입력
↓
b 경기 1 선수 픽
↓
a 경기 2(아스널전) 스코어 입력
↓
b 경기 2 선수 픽
↓
c 확인 — 두 경기를 한 화면에서 같이 보고, 한 번에 제출

v3~v6과 달라진 점

  • 매치 탭 완전 삭제 — 자유 전환 구조 자체가 폐기됐으니 탭이 필요 없습니다. 진행 표시는 기존 ProgressPips(steps.tsx)를 그대로 재사용하되, 더블 매치위크에서는 점 3개 대신 5개(a-b-a-b-c)로 늘렸습니다 — 컴포넌트 자체는 그대로, 개수만 세션이 다루는 스텝 수에 맞춥니다.
  • a·b 단계(스코어·픽) 레이아웃: 지금 싱글 매치 화면과 완전히 동일합니다 — 매치 라벨도, 다른 경기 정보도 없이 "경기 예측"/"선수 예측"이라는 기존 제목 그대로입니다. 그래서 4개 화면을 다 그리지 않고 1단계(a, 5점 중 1번째)만 실제로 그렸습니다.
  • c단계(확인)만 예외적으로 두 경기를 같이 보여줍니다 — 확인 화면은 원래도 "전체를 검토"하는 화면이라 여러 경기를 한 번에 보여주는 게 자연스럽고, 실제로 PredictionFlowClient.tsx의 기존 isMulti 확인 단계가 이미 이 패턴(MatchLabel + SummarySection ×2, 경기별로 반복)을 갖고 있어 그대로 재사용했습니다. a·b 단계를 "레거시라 없앤 것"과는 다른 얘기입니다 — 없앤 건 isMulti의 스코어·픽 "입력" 단계 스택(경기별 BudgetBar, "그대로 적용")이고, 확인 단계의 경기별 요약 패턴은 그대로 씁니다.
  • 제출 버튼 하나 — 확인 화면 맨 위에 "울브스전 2-1 · 아스널전 1-1" 같은 합산 요약 줄을 따로 두지 않았습니다. 각 경기 블록이 이미 스코어를 보여주고 있어 또 요약하면 중복이라고 판단했습니다. 버튼은 하단에 "제출하기" 하나만 두어 "이 화면에 보이는 전부가 한 번에 나간다"는 걸 표현합니다.

3-1. a단계 예시 — 경기 1 스코어 입력 (5점 pill 중 1번째)

b(경기 1 픽)·a(경기 2 스코어)·b(경기 2 픽) 3개 화면은 이 화면과 레이아웃이 완전히 동일하고 pill 위치만 다릅니다(각각 2/5, 3/5, 4/5) — 반복이라 따로 그리지 않았습니다.

"제출하기"를 누르면 기존 제출 확인 모달("이대로 제출할까요?")이 뜹니다 — 이 모달은 이번 변경과 무관하게 그대로이므로 따로 그리지 않았습니다. 다만 요약 라벨은 ${'{'}pending.length{'}'}경기 예측 그대로 쓰면 "2경기 예측"이 되어 이번 재확정(한 번에 제출)과 자연히 맞습니다.

확정 사항 갱신

1. "그대로 적용"(픽 복사) 기능 — 삭제 유지(경기마다 픽을 새로 고름).
2. 제출 방식 — 재확정(번복): "경기마다 따로 제출" → 확인 화면에서 두 경기를 한 번에 제출로 되돌아갔습니다.
3. 매치 탭 — 폐기: v3~v6에서 만든 자유 전환 탭 UI는 전부 폐기하고, 5점 ProgressPips로 대체합니다.
