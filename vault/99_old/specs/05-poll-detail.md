# 05 — 투표 상세 페이지 (/polls/[id])

최종 업데이트: 2026-09-04 (투표 정리 프로젝트, TEA-25/26/27/29 반영 — 코드 기준으로 갱신)

일반 투표(`type: 'poll'`)는 `PollClient.tsx` 하나가 렌더한다. 옛 `TypeAPollClient.tsx`/`TypeBPollClient.tsx` 두 컴포넌트는 TEA-26에서 병합·삭제됐고, 화면 분기는 `poll.player_id` 유무다 — 있으면 "poll 전체 선수 연결"(선수 대상 레이아웃), 없으면 "선택지별 선수 연결"이 가능한 선택형 레이아웃. 전체 평점(`type: 'overall_rating'`)은 별도 `OverallRatingPollClient.tsx`(이 문서 범위 밖).

## 공통 레이아웃 구조

```
┌─────────────────────────────┐
│  상단 고정 헤더 (뒤로가기)    │  ← AppHeader(PollPageHeader의 mobileBack), 플로팅 버튼 아님
├─────────────────────────────┤
│  [표지 이미지 160/252px]     │  ← 콘텐츠와 함께 스크롤(모바일 160px / 데스크탑 252px)
│   (선수 대상만) 하단 그라데이션+제목 오버레이
├─────────────────────────────┤
│  콘텐츠 영역 (스크롤)         │
│  · (선택형만) 제목 + 상태뱃지 + 작성일 + 설명
│  · 선택지 UI — 세로 라디오 리스트
│  · 선수 정보 카드 (선수 대상만)
└─────────────────────────────┘
│  [투표하기] ← 하단 고정        │
└─────────────────────────────┘
```

### 뒤로가기

- 상단 고정 헤더(`AppHeader`, `mobileBack`)에 있다 — 표지 이미지 위 플로팅 pill 버튼은 애초에 구현된 적이 없다(옛 스펙 폐기).

### 표지 이미지

- 높이: 모바일 160px / 데스크탑(`sm:` 이상) 252px 반응형(`h-[160px] sm:h-[252px]`, TEA-27) — 이전엔 화면마다 150/160/252px가 섞여 있었다.
- `poll.player_id`가 있으면(선수 대상 레이아웃): 커버 위에 마감 뱃지(D-N 또는 "마감")와 제목을 흰 텍스트로 오버레이(그라데이션). 커버는 좌우 여백 없이 `rounded-lg`.
- `poll.player_id`가 없으면(선택형 레이아웃): 제목을 커버 위에 얹지 않고, 커버 아래 별도 글 컨테이너(`rounded-lg border border-neutral-weak bg-surface`)에 상태 뱃지·작성일·작성자·설명과 함께 표시. 결과 화면(`ResultView.tsx`)도 커버를 카드 밖 독립 블록으로 두는 같은 처리를 쓴다.
- 커버 이미지 소스 우선순위: `thumbnail_url` → `player.photo_url` → placeholder.
- 유형 뱃지(평가/선택 구분) 없음 — `PollType` 통합(TEA-26)으로 타입 개념 자체가 없어짐.

## 콘텐츠 영역

- 선택지: 세로 라디오 리스트(`RadioOption`, `role="radiogroup"`) — 캐러셀이 아니다. 코드에 "의도적으로 캐러셀에서 바꿨다"는 취지의 처리가 이미 있었고, 이번 정리에서도 변경하지 않았다.
- 선택지 중 하나라도 선수/이미지가 연결돼 있으면 각 옵션 앞에 원형 썸네일(선수 사진 또는 커스텀 이미지, 없으면 라벨 이니셜)을 표시.
- 옵션 보조 라벨: 연결된 선수가 있으면 포지션·등번호, 없으면 옵션 설명(`option.description`).
- 선택지 개수 안내 문구("선택지 N개 · 하나만 고를 수 있어요")는 선택형(선수 대상 아님) 레이아웃에서만 표시.
- 선수 정보 카드: `poll.player_id`가 있을 때만 콘텐츠 하단에 표시(아바타 44px 원형 + 이름 + 포지션·등번호).
- 투표 설명(`poll.description`)은 있을 때만 표시.
- 카드 부제(예: "N명의 후보") 없음 — 지금처럼 부제 없는 상태 유지.

## 제출 버튼

- 화면 최하단 고정(`StickyActionBar`) — 모바일은 뷰포트 기준 `fixed`, 데스크탑(`sm:` 이상)은 고정을 풀고 콘텐츠 흐름 안에 자연스럽게 놓인다.
- 버튼 자체는 기본 `Button` 컴포넌트 스타일(`rounded-sm`)을 쓴다 — 옛 스펙의 "border-radius: 0, 전체 너비 full-bleed" 방식이 아니다.
- 선택 전: disabled. 선택 후: Primary 색 활성화.

## 확인 모달 (공통 — Bottom Sheet)

- `ConfirmContent` — "이 선택으로 투표하시겠어요? 제출 후에는 변경할 수 없습니다"
- 버튼 배치: 취소(outlined) 좌측, 최종 제출(contained) 우측
- 최종 제출 → `submitVote()` → `votes` 테이블 INSERT → 화면 새로고침(결과 화면으로 전환)
- 중복 투표: DB UNIQUE 제약으로 차단 → "이미 참여한 투표입니다" 토스트

## 결과 화면 (투표 후 / 재방문) — `ResultView.tsx`

### 결과 계산 방식
- 실시간 계산: 화면 진입 시 DB에서 `votes` 집계 → 퍼센트 계산. 새로고침 시 최신 데이터 반영. 별도 캐싱 없음.

### 레이아웃
- 상단 고정 헤더(뒤로가기 + 수정 링크는 모바일 헤더/데스크탑 본문에 각각)
- 커버 이미지(160/252 반응형, 카드 밖 독립 블록)
- 흰 카드 안: 제목 + 작성일/작성자 → 결과 패널(회색 배경, "현재 결과"/"최종 결과") → 참여자 수
- **최다 득표 전용 카드 없음** — 결과는 `count` 내림차순으로 정렬된 하나의 리스트(`ResultProgress`)이며, 1위 항목만 `highlighted`로 강조 표시된다(옛 스펙의 별도 "최다 득표" 카드 UI는 폐기).
- 내 선택 항목은 리스트 안에서 별도 표기.
- 댓글 섹션은 결과 카드 밖에 위치, 참여자만 작성 가능(불변 제약).

## 마감된 투표

- 투표 UI 없음, 결과 화면만 표시.
- 미참여자도 결과 열람 가능.

## 에러 처리

| 상황 | 처리 |
|------|------|
| 이미 투표한 사용자 접근 | 투표 UI 대신 결과 화면 바로 표시 |
| 마감된 투표 접근 | 결과 열람 가능, 투표 버튼 없음 |
| 투표 제출 실패 (네트워크) | 에러 토스트 + "다시 시도해주세요" |
| 중복 투표 시도 (비정상 접근) | "이미 참여한 투표입니다" 토스트 |
| 비로그인 제출 시도 | 로그인 유도 모달 (→ 02-auth.md) |
| 존재하지 않는 poll id | 404 → `/` 리다이렉트 |
