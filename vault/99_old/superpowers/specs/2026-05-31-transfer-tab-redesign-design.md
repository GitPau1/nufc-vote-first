# 이적 탭 개편 설계서

## 1. 목표

- 이적 탭을 `현재 시즌 기준의 In/Out 이력` 중심으로 재구성한다.
- 선수의 `현재 상태`와 `이적 이력`을 분리해 관리한다.
- 임대 복귀처럼 `복귀는 있지만 이적은 아닌 경우`를 구분한다.
- 기존 `farewell`은 작별 콘텐츠로 유지하고, 이적 탭의 책임에서 분리한다.

## 2. 합의된 기준

### 현재 시즌

- 현재 시즌은 날짜 자동 계산이 아니라 전역 설정값으로 관리한다.
- 전역 설정값은 기존 구단 설정 데이터에 `current_season` 필드를 추가해 저장한다.
- 이적 탭은 항상 `club_status.current_season`과 일치하는 이력만 노출한다.

### 이적 시점

- 이적 시점은 `시즌`만 저장한다.
- 실제 날짜는 이번 개편 범위에 포함하지 않는다.

### 상대 구단명

- 상대 구단명이 비어 있으면 화면에는 `Free Agent`로 표시한다.

### 복귀와 이적의 구분

- `복귀`는 선수 상태를 구단 내로 되돌리는 행위다.
- `이적`은 이적 탭에 기록되어야 하는 시즌 이력이다.
- 따라서 모든 복귀가 이적은 아니다.

## 3. 도메인 재정리

### 선수 상태

선수 상태는 대시보드와 선수 관리 화면에서 사용하는 현재 소속 상태다.

- 구단 내 선수
- 구단 외 선수
- 필요 시 임대, 1군, U21 같은 세부 상태

이 값은 "지금 이 선수가 어디에 속해 있는가"를 보여준다.

### 이적 이력

이적 이력은 이적 탭에서 사용하는 시즌 단위 기록이다.

- 방향: `In` 또는 `Out`
- 시즌: 전역 현재 시즌과 비교 가능한 값
- 상대 구단명: `from` 또는 `to`에 사용
- 유형: 영입, 임대 영입, 이적, 임대, 방출 등

이 값은 "이번 시즌에 어떤 이동이 있었는가"를 보여준다.

## 4. 데이터 역할 분리

### 추천안

- `farewell`은 유지한다.
- `farewell`의 역할은 작별 페이지, 작별 메시지, 댓글 같은 콘텐츠다.
- 이적 탭은 별도 `transfers` 이력 모델로 분리한다.

이 구조를 선택한 이유는 다음과 같다.

- `farewell`은 본질적으로 팀을 떠나는 선수에 대한 콘텐츠 성격이 강하다.
- 새 이적 탭은 `In/Out` 양방향을 모두 포함해야 한다.
- 따라서 `farewell`에 `In`까지 억지로 넣는 것보다, 이적 전용 모델을 두는 편이 책임이 명확하다.

### 대안 검토

#### 1. farewell 확장

- 장점: 기존 코드를 가장 적게 바꾼다.
- 단점: `farewell`이라는 이름과 실제 역할이 어긋난다.

#### 2. farewell 유지 + transfers 분리

- 장점: 콘텐츠와 이력을 분리할 수 있어 의미가 가장 명확하다.
- 단점: 조회 경로와 관리자 입력 경로를 새로 추가해야 한다.

#### 3. farewell 제거

- 장점: 모델 수를 줄일 수 있다.
- 단점: 작별 페이지와 댓글 구조를 함께 재설계해야 해 범위가 커진다.

추천은 `farewell 유지 + transfers 분리`다.

## 5. 관리자 동작 규칙

### 새 선수 생성

- 관리자는 선수를 새로 생성할 수 있다.
- 이때 옵션에 따라 `이번 시즌 In 이력 생성`을 함께 수행할 수 있다.
- 이력 생성이 선택되지 않으면 선수만 추가되고 이적 탭에는 노출되지 않는다.

### 구단 외 선수 복귀

- 구단 외 선수는 다시 구단 내로 복귀시킬 수 있다.
- 이때 체크박스의 의미는 `단순 복귀`다.

규칙:

- 체크 `ON`
  - 단순 복귀 처리
  - 선수 상태만 구단 내로 변경
  - 새 `In` 이력은 생성하지 않음
- 체크 `OFF`
  - 실제 재영입 처리
  - 선수 상태를 구단 내로 변경
  - 이번 시즌 `In` 이력 생성

이 규칙은 임대 복귀를 기본 흐름으로 보는 운영 방식에 맞춘다.

### 구단 내 선수 이탈

- 이적, 임대, 방출 같은 이탈은 `Out` 이력으로 기록한다.
- 동시에 선수 상태를 구단 외 또는 적절한 세부 상태로 변경한다.

## 6. 탭 표시 규칙

### 필터 기준

- 이적 탭은 현재 시즌 이력만 표시한다.
- 기본적으로 전체 과거 시즌 탐색은 이번 개편 범위에서 제외한다.

### 레이아웃

- 카드형보다 간략한 1줄 리스트형으로 표시한다.
- 각 항목은 `flex` 기반으로 여백을 제외한 가용 너비를 채운다.
- 한 항목의 내부 구조는 아래와 같다.

1. 좌상단에 `In` 또는 `Out` 상태
2. 중앙에 선수 사진
3. 사진 아래 중앙 정렬 선수 이름
4. 이름 아래 중앙 정렬 `to {구단명}` 또는 `from {구단명}`

### 문구 규칙

- `In`이면 `from {club}`
- `Out`이면 `to {club}`
- 상대 구단명이 없으면 `{club}` 자리에 `Free Agent`

## 7. 화면/기능 영향 범위

### 대시보드

- 선수 목록을 `구단 내 선수`와 `구단 외 선수` 기준으로 나눌 수 있어야 한다.
- 이 구분은 이적 이력이 아니라 `현재 상태` 기준이다.

### 이적 탭

- 기존 farewell 중심 목록 대신 현재 시즌 transfer 이력 목록을 사용한다.
- 표시 대상은 `In`과 `Out` 모두 포함한다.

### farewell

- farewell 상세 페이지와 댓글 기능은 유지한다.
- farewell은 계속 `작별 콘텐츠`로 남는다.
- 단, 이적 탭의 메인 데이터 소스로는 사용하지 않는다.

## 8. 검증 기준

- 현재 시즌 전역 설정값을 바꾸면 이적 탭 노출 항목도 함께 바뀌어야 한다.
- 새 선수 생성 시 선택에 따라 `In` 이력이 생기거나 생기지 않아야 한다.
- 구단 외 선수 복귀 시 체크 `ON`이면 상태만 바뀌고 이적 탭에는 추가되지 않아야 한다.
- 구단 외 선수 복귀 시 체크 `OFF`면 `In` 이력이 생성되어야 한다.
- 상대 구단명이 비어 있으면 `Free Agent`로 표시되어야 한다.
- farewell 콘텐츠는 유지되지만, 이적 탭 목록과 직접 결합되지 않아야 한다.
