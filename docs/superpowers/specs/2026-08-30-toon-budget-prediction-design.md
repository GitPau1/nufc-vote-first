# 승부예측 '툰' 예산제 + 순위 차등 배점 설계

- 작성일: 2026-08-30
- 상태: 설계 승인 대기 (구현 계획 전)
- 대상 기능: 승부예측(match prediction)의 선수 픽 가중치 → '툰' 예산제 전환 및 점수 산식 재설계

## 1. 배경 / 문제

현재 승부예측은 선수마다 **배당(`prediction_multiplier`)**을 두고, 점수를 `평점 ≥ 7이면 배당 × 2.4, 아니면 0`으로 계산한다(임시 산식, 관리자 수동 입력, 산식 미확정 상태 — `supabase/migrations/20260821120000_create_predictions.sql:113-116`, `20260821110000_create_season_squads.sql:31-32`).

이 "배당" 개념을 두 가지로 분리·재정의한다:
1. **선택 제약**: 배당 대신 '툰'이라는 가상 화폐로 예산 안에서 선수를 뽑는다.
2. **점수 산식**: 배당 배율이 아니라, 실제 경기 활약(평점 순위)으로 점수를 매긴다.

## 3. 상세 설계

### 3.1 툰 예산과 선수 비용

- 각 선수(포지션별 픽 후보)는 **1~3툰**의 비용을 가진다. 실력이 높을수록 비싸다.
- 유저는 총 **5툰** 예산 안에서 DEF/MID/FWD 각 1명씩, 세 명의 비용 합계가 5툰을 넘지 않게 뽑는다.
- 산술적 결과: 3툰 픽은 최대 1명만 가능(3+3=6 > 5). 실질 조합은 `{3,1,1}`(스타 몰빵) 또는 `{2,2,1}`(분산) 두 갈래.
- **비용은 점수에 전혀 영향을 주지 않는다.** 비싼 선수의 메리트는 "그 포지션에서 상위권일 확률이 높다"는 것 자체이며, 대신 예산을 많이 먹어 다른 포지션에서 도박을 강요한다.

#### 비용 배정 규칙 (월별 자동 산정)

- 배정 방식은 **규칙으로 제약**한다(관리자 자유 배정 아님).
- **매달 초**, 각 포지션 후보를 **지난 30일(또는 직전 달 경기) 평균 평점**으로 정렬한다.
- 순위로 티어 배정(= 인원 상한):
  - **1위 → 3툰** (포지션당 최대 1명)
  - **2~3위 → 2툰** (포지션당 최대 2명)
  - **4위 이하 → 1툰** (나머지)
- 이러면 "3툰 1명·1툰 최소 1명 보장"이 자동 충족되고 예산이 항상 조인다. 포지션당 후보는 약 **7~8명**이다.
- "지난달 잘한 선수 = 이번달 비쌈"이 되어, 이번 경기에서 그 선수가 실제로 잘할지가 예측의 핵심이 된다.
- **[구현 시 확인]** 후보가 3명 이하인 포지션(부상·로테이션)에서의 티어 상한 예외 처리.

### 3.2 선택 구조

- 포지션 3개: DEF / MID / FWD. 각 1명씩 고정. 골키퍼 없음.
- 제출 검증: 세 픽이 서로 다른 선수(기존 `predictions_distinct_picks` 유지) + **비용 합계 ≤ 5툰**(신규 검증).

### 3.3 점수 산식

**픽 점수 (포지션별, 차등 배점):**

- 각 포지션 후보들을 그 경기 **평점(`fixture_player_ratings.rating`)** 내림차순으로 정렬한다.
- 유저가 뽑은 선수의 순위에 따라:
  - 1위 → **4점**
  - 2위 → **2점**
  - 3위 → **1점**
  - 4위 이하 또는 평점 없음(미출전) → **0점**
- 세 포지션 합산으로 픽 점수 최대 **12점**.
- 후보가 포지션당 약 7~8명이므로, 상위 3명만 점수를 받는다(하위·미출전은 0점).

**스코어 점수 (기존 유지·상향):**

- 스코어 정확 적중 → **8점**
- 승무패만 적중(스코어는 틀림) → **5점**
- 그 외 → 0점
- (8점과 5점은 배타적 — 둘 다 받지 않음. 정확 적중이면 8점만.)

**경기 총점 = 픽(≤12) + 스코어(≤8) = 최대 20점.**

- **동점 처리(확정)**: **표준 경쟁 순위(1-2-2-4 방식)** — 동점자는 같은 순위·같은 점수를 받고, 그 아래 순위는 동점 인원수만큼 밀린다. 예: 두 명이 공동 2위(각 2점)면 그다음은 4위(0점).

### 3.4 과거 점수 소급 정책

- **전환 시 1회 재채점**: 툰 체계로 넘어갈 때, 이미 배당제로 제출된 과거 예측들도 새 순위 차등 산식으로 다시 채점한다(옛 예측도 결국 DEF/MID/FWD 선수를 고른 것이므로 그 선수 평점 순위로 재채점 가능).
- **예산 소급 없음**: 과거 예측은 5툰 예산 없이 뽑은 것이므로, 예산 초과라도 **소급 무효 처리하지 않는다**. 예산 검증은 **앞으로의 새 제출에만** 적용한다.
- **이후 마감 동결**: 매달(또는 매주) 마감 시점에 점수를 계산해 **동결**한다. 이후 산식·평점을 튜닝해도 이미 정산된 과거 순위는 흔들리지 않는다.
- **[구현 시 확인]** 이 리포엔 이미 `prediction_results_week_settled`(주간 정산본 view)가 있다 — 기존 동결 메커니즘의 정확한 동작을 확인해 위 정책과 맞춘다.

### 3.5 채택하지 않은 요소와 근거

- **무실점(clean sheet)**: 선수/경기별 clean sheet 컬럼 없음. 팀 단위(`fixtures.home_score/away_score`)로만 유도 가능. 순위제 도입으로 포지션 색깔이 이미 생겨 불필요 판단.
- **공격포인트(득점·도움)**: 경기별 데이터 없음(있는 건 `player_season_stats` 시즌 누적뿐, 경기 링크 없음). 경기별로 쓰려면 신규 테이블+입력 UI 필요. 게다가 FotMob 평점이 골·도움을 이미 반영하므로 "공격 잘한 선수 = 평점 높음 = 순위 높음"으로 대체됨.

## 4. 밸런스 검증 (몬테카를로 시뮬레이션)

`scratchpad/toon-balance-sim.mjs`로 50만 경기를 시뮬해 픽 전략별 기대점수를 비교했다. 가정: 포지션당 3툰×1 / 2툰×2 / 1툰×5(실제 후보 ~8명), 경기 노이즈 σ=0.7. "전략 격차" = 더 나은 전략이 다른 전략보다 기대점수가 앞선 비율.

| 배점 방식 / 시나리오 | `{3,1,1}` 스타 | `{2,2,1}` 분산 | 전략 격차 | 0점 경기 |
|---|---|---|---|---|
| 이진(1위만 정답), 6후보 기본 | 2.32점 | 1.68점 | +38% | 47.5% |
| 차등 4/2/1, 6후보 기본 | 3.66점 | 3.34점 | +9.6% | 7.4% |
| **차등 4/2/1, 8후보 기본**(격차 큼) | 3.23점 | 2.85점 | **+13%** | 12.8% |
| 차등 4/2/1, 8후보 격차압축(7.1/6.9/6.7) | 2.83점 | 2.75점 | +3% | 21.0% |

**결론:** (수치는 실제 후보 수인 8후보 기준)
- **차등 배점이 밸런스의 주 무기다.** 이진에선 스타 몰빵이 압도적(6후보 +38%)이었으나 차등 4/2/1로 전략 격차를 **+13%(8후보 기본)**, 스쿼드가 고르면 +3%까지 눌러 분산 전략을 살린다.
- **비싼 선수 메리트는 유지된다** — 스타 1위 확률 43%(8후보), `{3,1,1}`이 여전히 근소 우세.
- **0점 경기 대폭 감소** — 이진 47.5% → 차등 12.8%(8후보 기본). 2·3위 부분점수로 유저 좌절감 감소.
- **예산은 건강하게 조인다** — 예산 미사용 전략(`{2,1,1}`·`{1,1,1}`)은 확실히 손해.
- 밸런스의 근본 변수인 "실력 격차"는 실제 평점에 달려 있어 코드로 못 정한다. 운영 레버는 **차등 배점(고정)**과 **툰 비용 인심(관리자)** 두 가지다.
- **참고**: 차등 점수 인심은 **포지션당 후보 수**에 따라 달라진다(후보 4명이면 3명이 점수, 8명이면 상위 3명만). 후보 풀 크기는 관리자 운영 사항.

## 5. 구현 영향 (변경 대상 — 상세 계획은 별도)

### DB / 마이그레이션
- **(C-2 확정)** `season_squads`에 **신규 컬럼 `pick_cost`**(1~3 정수 제약) 추가. 옛 `prediction_multiplier`는 마이그레이션 후 제거.
- **월별 비용 산정 잡**: 매달 각 포지션 후보의 직전 달 평균 평점 순위로 `pick_cost`를 갱신하는 배치/함수(3.1 규칙). 실행 트리거는 구현 시 결정(cron edge fn 등).
- **(D-1 확정)** `predictions`에 **픽별 비용 스냅샷 저장**(예: `def/mid/fwd_cost`). 점수엔 무관하나, 비용이 월별 가변이라 **과거 스쿼드의 그 시점 비용을 보존**하기 위함. 옛 배당 스냅샷(`def/mid/fwd_multiplier`)은 제거.
- `prediction_pick_points(rating, multiplier)` 함수 폐기. 점수는 이제 **경기·포지션별 후보 순위**에 의존하므로, 단일 행 함수가 아니라 **후보를 평점으로 순위 매기는 뷰/윈도우 함수**(`prediction_results` view 재작성, 표준 경쟁 순위 → 4/2/1)로 바뀐다.
- `prediction_match_points` 배점 3/2 → **8/5** 상향.
- **(과거 데이터 확정)** 전환 시 옛 predictions를 새 산식으로 **1회 재채점**, 예산 소급 무효는 없음. 이후는 마감 동결(`prediction_results_week_settled` 메커니즘 확인 후 정렬).

### 앱 / UI
- 제출 검증(`frontend/src/lib/predictions/submit.ts`): 비용 합계 ≤ 5툰 규칙 추가, 배당 재조회 로직을 비용 재조회로 전환.
- 후보 조회(`frontend/src/lib/queries/squads.ts`): `multiplier` → 비용 필드.
- 선택 UI: 선수별 배지 `×N.N`(배당) → `N툰`(비용), **예산 표시(5툰 중 사용/잔여)**, 초과 시 제출 차단. 관련: `PlayerPick.tsx`, `PredictionFlowClient.tsx`.
- 결과 화면(`PredictionResult.tsx`, `lib/predictions/result.ts`): 순위 차등 점수 및 "그 포지션 1·2·3위" 표시 반영.
- 관리자: 비용 배정 입력 UI(현재 배당 전용 입력 UI 없음 — 신규 필요 가능성). 평점 입력은 기존 `/admin/ratings` 유지.
- 도메인 타입(`frontend/src/types/database.ts` 수동 관리): 스키마 변경 동기화.

### 테스트
- `submit` 관련 테스트: 예산 검증 케이스 추가. 결과 화면 문자열 검사 테스트(정규식 기반)는 순위 표시로 바뀐 자리 기준 재작성.

## 6. 결정 확정 로그

- **A. 툰 비용 배정** → **월별 재산정**, 직전 달 평균 평점 순위로 티어(3툰×1/2툰×2/1툰×나머지). ✅
- **B. 동점 처리** → **표준 경쟁 순위(1-2-2-4)**. ✅
- **C. 비용 컬럼** → **신규 컬럼 `pick_cost`**, 옛 `prediction_multiplier` 제거. ✅
- **D. 비용 스냅샷** → **저장함**(월별 가변이라 과거 스쿼드 보존용, 점수엔 무관). ✅
- **E. 기존 제출 데이터** → **1회 재채점 + 예산 소급 무효 없음 + 이후 마감 동결**. ✅

### 구현 시 확인 (설계 확정, 세부는 계획 단계)
- 후보 3명 이하 포지션의 티어 상한 예외 처리.
- 월별 비용 산정 잡의 실행 트리거(cron/edge fn 등).
- `prediction_results_week_settled` 기존 동결 메커니즘의 정확한 동작 → 과거 점수 정책과 정렬.

## 7. 만점 배분 근거 (숫자 확정 로그)

- 포지션 정답(1위) 4점 × 3 = 12점.
- 스코어 정확 8점(포지션 1위의 2배 — 정확 예측을 무겁게), 승무패만 5점(포지션 1위보다 약간 위).
- 경기 만점 20점.
