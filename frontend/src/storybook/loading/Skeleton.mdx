# Skeleton

컴포넌트가 아니라 패턴이다. `Skeleton`이라는 export는 없고, `globals.css`의 `.animate-skeleton` 유틸리티와 `components/primitives/navigation-loading.tsx` 안의 내부 함수(`SkeletonBlock`, `PollsSkeleton`, `PredictionsSkeleton`, `PlayersSkeleton`, `MenuSkeleton`)로만 존재한다. 이 페이지의 스토리는 그 마크업을 그대로 복제한 것이다 — 소스를 export하도록 고치지 않았으므로, 원본이 바뀌면 여기도 같이 고쳐야 한다.

`NavigationLoading`은 `document`의 링크 클릭을 캡처해서 뜨는 클라이언트 컴포넌트라 props로 상태를 열 수 없다. 그래서 컴포넌트 자체를 `component`로 붙이는 대신 형상별 스토리로 쪼갰다.

## 구성 요소

<Canvas of={SkeletonStories.Primitives} />

placeholder 한 칸은 `SkeletonBlock` 하나다 — 겉면이 `bg-disabled`로 자리를 잡고, 안쪽 `<div>`가 `.animate-skeleton`(1.15s shimmer)을 돌린다. shimmer 그라디언트가 겉면 radius를 넘어가지 않도록 `overflow-hidden`이 필수다.

형상 차이는 radius로만 낸다. 값은 새로 정하지 않고 [Radius](?path=/docs/foundations-radius--docs)가 **그 자리에 들어올 실물**에 배정한 값을 그대로 쓴다 — 스켈레톤이 자기만의 radius 체계를 갖지 않는다는 뜻이다.

| 무엇의 자리인가 | 클래스 |
|---|---|
| 텍스트 한 줄, 작은 배지, 작은 아이콘 | `rounded-xs` |
| 원형 아바타(선수 사진 등) | `rounded-pill` |
| 썸네일·아이콘 박스 | `rounded-md` |
| 히어로 등 큰 미디어 | 카드에 `animate-skeleton bg-disabled`를 직접 얹는다 (안쪽 래퍼 없이) |

애니메이션 토큰 자체는 [Motion](?path=/docs/foundations-motion--docs), 로딩이 상태 체계에서 어디에 속하는지는 [State](?path=/docs/foundations-state--docs)를 본다.

## 화면 로딩

경로에 따라 5가지로 갈린다 (`getLoadingVariant`).

| 경로 | 무엇이 뜨는가 |
|---|---|
| `/`, `/polls` | `PollsSkeleton` |
| `/predictions` | `PredictionsSkeleton` |
| `/players` | `PlayersSkeleton` |
| `/menu` | `MenuSkeleton` |
| 그 외 전부 | 상단 진행 바만 (`TopBarOnly`) |

경로 판정은 정확 일치라 `/predictions/[weekKey]` 같은 하위 경로는 스켈레톤 없이 상단 진행 바로 떨어진다.

스켈레톤은 **그 화면의 실제 레이아웃을 그대로 흉내낸다** — 행 높이(`h-32`, `h-[68px]`, `h-14`), 구분선, 탭의 활성 밑줄까지 맞춘다. 빈 박스 하나로 대체하지 않는 게 이 패턴의 규칙이다. 새 화면에 스켈레톤을 붙일 때는 그 화면 마크업을 복사해서 텍스트·이미지 자리를 `SkeletonBlock`으로 치환하는 순서로 만든다.

## 스토리와 실제 렌더의 차이

스토리는 화면 스켈레톤을 감싸는 오버레이 래퍼를 뺐다. 원본은

```
fixed inset-x-0 bottom-[64px] top-0 z-[100] mx-auto flex w-full max-w-shell
flex-col bg-page/95 backdrop-blur-sm
```

로 뷰포트 전체를 덮는데, 그대로 두면 Storybook 캔버스가 아니라 Storybook UI 전체를 덮어버린다. 대신 375px 박스로 감싸 폭만 맞췄다. `bottom-[64px]`는 BottomNav가 차지하는 높이를 비워두는 값이다 — 스켈레톤이 하단 내비게이션을 덮지 않아야 로딩 중에도 탭 이동이 가능하다. `navigation-loading.test.mjs`가 이 값을 감시한다. (BottomNav 자체는 고정 높이가 아니라 `pt-2 + 아이콘 + 라벨 + pb-4`로 계산되는 콘텐츠 높이라, BottomNav 내부 간격을 바꾸면 이 64px도 같이 맞춰야 한다.)

접근성도 오버레이 쪽에 붙어 있다: 래퍼가 `role="status"` + `aria-label`을 갖고 안쪽 스켈레톤 본문은 전부 `aria-hidden="true"`다. 스크린리더에는 "페이지를 불러오는 중" 한 문장만 읽히고 placeholder 더미는 읽히지 않는다. 새로 스켈레톤을 만들 때도 본문에 `aria-hidden`을 빠뜨리지 않는다.

## 언제 쓰지 않는가

- 화면 일부만 늦게 오는 경우에는 전체 화면 스켈레톤을 띄우지 않는다. 지금 `.animate-skeleton`을 쓰는 곳은 `NavigationLoading` 한 곳뿐이고, 나머지 부분 로딩은 스켈레톤 없이 처리하고 있다.
- 화면 전환 로딩에 스피너를 쓰지 않는다 — `navigation-loading.test.mjs`가 `NavigationLoading`에 `animate-spin`이 들어오는 걸 막고 있다. 스피너는 제출 버튼의 pending 표시(`Loader2 animate-spin`, 투표 클라이언트 3곳)처럼 "이미 보이는 요소가 작업 중"일 때만 쓴다.
