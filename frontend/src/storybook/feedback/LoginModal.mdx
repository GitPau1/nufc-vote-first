# LoginModal

`components/polls/LoginModal.tsx`. 비로그인 사용자에게 그 화면 위에 띄우는 로그인 모달이다. 진입 맥락은 두 가지 — 사용자가 스스로 로그인을 시작한 경우(헤더·메뉴)와 하려던 행동이 막힌 경우(투표·승부예측). `triggerAction`이 그 둘을 갈라 설명 문구를 바꾼다.

이 서비스에는 `/login` 페이지가 없다. 로그인은 언제나 이 모달로만 일어난다 — 그래서 "로그인 화면으로 보낸다"는 선택지 자체가 없고, 어디서 막혔든 그 자리에서 모달을 띄운다.

## triggerAction이 설명 문구를 가른다

`triggerAction: 'login' | 'vote' | 'predict'`. **기본값이 없다** — 문구를 결정하는 값이라 호출부가 자기 맥락을 반드시 명시한다. 이 값은 `auth_prompt_viewed` 이벤트의 `trigger_action` 속성으로도 그대로 나간다.

문구는 두 갈래다. 제목(`로그인이 필요해요`)과 자물쇠 아이콘은 공통이고, `SheetDescription`만 갈린다.

| `triggerAction` | 설명 문구 |
| --- | --- |
| `login` | 로그인하면 투표에 참여하고 내 기록을 볼 수 있어요 |
| `vote` | 투표에 참여하려면 로그인해주세요 |
| `predict` | 승부예측에 참여하려면 로그인해주세요 |

- **케이스 1 — 일반 로그인(`login`)**: 사용자가 특정 행동에 막힌 게 아니라 스스로 로그인을 시작한 경우다. 여기서 "투표에 참여하려면"이라고 말하면 하지도 않은 행동을 전제하게 되니, 대신 로그인해서 얻는 것을 말한다.
- **케이스 2 — 행동 유도(`vote`, `predict`)**: 하려던 행동이 막혀서 뜬 경우다. 막힌 그 행동을 문구에 그대로 담는다. 새 유도 지점이 생기면 값을 추가하고 문구를 한 줄 더 쓴다(`LoginModal.tsx`의 `TRIGGER_DESCRIPTION` 맵).

예전엔 이 값이 analytics 속성으로만 쓰여서 헤더 로그인 버튼에서 열어도 "투표에 참여하려면 로그인이 필요합니다"가 떴다. `components/polls/login-modal.test.mjs`가 이제 (1) 문구가 값별로 실제로 다른지, (2) 호출부마다 맥락에 맞는 값을 넘기는지를 소스 문자열로 고정한다.

타입에만 있고 넘기는 곳이 없던 `'comment'`·`'create_poll'`은 없앴다 — 값이 문구를 가르게 된 뒤로는 죽은 값이 곧 아무도 못 보는 문구다. 댓글 작성은 투표 참여자만 가능해서 비로그인 사용자가 도달하지 못하고, 투표 생성 페이지는 `RequireAuthModal`(`login`)을 쓴다.

## RequireAuthModal — 유일한 래퍼

`components/auth/RequireAuthModal.tsx`(24줄)는 이 모달을 `open` 고정 + `onClose={() => router.push('/')}` + `triggerAction="login"`으로 감싼 것뿐이다. 로그인 없이는 볼 내용이 없는 화면에서 `redirect('/login')` 대신 쓴다: `app/admin/page.tsx`, `app/polls/create/page.tsx`, `app/my/page.tsx`, `app/my/feedback/page.tsx`, `app/onboarding/page.tsx`.

닫기 = 홈으로 이탈이라 "닫고 그 화면에 머무르기"가 없다. 그게 유일한 차이라서 별도 컴포넌트 문서로 나누지 않고 여기 스토리 하나로 둔다.

## 실제 로그인은 Storybook에서 동작하지 않는다

`Google로 로그인`은 `supabase.auth.signInWithOAuth`로 실제 OAuth 리다이렉트를 시도하므로 Storybook에서는 정상적으로 안 된다. mock 모드 버튼(`데모로 바로 로그인`)은 서버 액션 `mockLogin`을 호출해서 역시 동작하지 않는다. 여기서는 렌더링과 열림/닫힘까지만 확인한다.

CTA 버튼 라벨과 아이콘은 `triggerAction`이 아니라 `lib/config.ts`의 `IS_MOCK`으로 갈린다 — Supabase 환경 변수가 있으면 `Google로 로그인`(+ Google 아이콘), 없으면 `데모로 바로 로그인`(⚡). **Storybook을 실행한 환경의 `.env.local`이 그대로 반영되므로 스토리에서 어느 쪽이 보이는지는 고정이 아니다.**

정리하면 이 모달에서 갈리는 축은 셋이고 서로 겹치지 않는다 — 설명 문구는 `triggerAction`, CTA 라벨은 `IS_MOCK`, 바텀시트/중앙 모달은 화면 폭. 예전엔 설명 문구도 `IS_MOCK`으로 덮여서(`데모 로그인으로 바로 참여할 수 있어요`) mock 모드에서는 맥락별 문구가 아예 보이지 않았는데, 그 분기는 없앴다. 데모 모드라는 사실은 CTA 라벨이 이미 말해준다.

모달이 열릴 때 `auth_prompt_viewed`를 전송하는데, Mixpanel 토큰(`NEXT_PUBLIC_MIXPANEL_TOKEN`)이 없으면 no-op이다.

## 구조

[BottomSheet](?path=/docs/feedback-bottomsheet--docs) 위에 얹혀 있어 모바일(`<768px`)은 바텀시트, 데스크톱은 중앙 모달로 뜬다. 예전엔 "메뉴에서는 항상 중앙 모달" 같은 `intent` prop 분기가 있었는데 없앴다 — 화면 폭이 유일한 기준이다. `components/polls/login-modal.test.mjs`가 이 규칙(그리고 CTA가 `outline`이 아닌 채움 버튼이라는 점, 맥락별 문구, 호출부별 `triggerAction` 값까지)을 소스 문자열로 검사하므로, 문구나 호출부를 고칠 때 그 테스트를 함께 본다.
