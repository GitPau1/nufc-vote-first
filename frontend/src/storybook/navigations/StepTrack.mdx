# StepTrack

승부예측 입력 플로우(`score` → `pick` → `confirm`) 안에서 **지금 어디쯤이고 몇 개가 남았는지**를 알려주는 진행 표시라, 콘텐츠가 아니라 Navigations에 둔다. 다만 노드를 눌러 이동하는 기능은 없다 — 이동은 각 스텝의 버튼이 하고 이 컴포넌트는 상태만 그린다.

`src/components/predict/steps.tsx` 한 파일이 5개를 내보낸다.

| export | 정체 | 쓰이는 곳 |
|---|---|---|
| `StepKey` | `'score' \| 'pick' \| 'confirm'` 타입 | `PredictionFlowClient`의 `useState<StepKey>('score')` |
| `STEP_META` | 3스텝의 key/name/desc/descMulti 배열 | 세 컴포넌트가 전부 이걸 순회한다 |
| `StepTrack` | 가로 트랙(원형 노드 + 커넥터, **라벨 없음**) | 모바일 상단 |
| `StepHero` | 현재 스텝의 타이틀 + 설명 | 모바일, 트랙 바로 아래 |
| `StepTrackVertical` | 세로 트랙(노드 + 이름, 활성 단계만 설명) | 데스크탑 좌측 사이드 |

## 상태 3가지

`STEP_META`의 인덱스와 현재 스텝 인덱스를 비교해 `done` / `active` / `pending`으로 갈린다. 세 컴포넌트가 같은 `StepCircle`을 공유한다.

| 상태 | 노드 | 커넥터 |
|---|---|---|
| `done` | `bg-brand-solid` 채운 원 + `text-on-solid` 체크 | 앞 구간 `bg-brand-solid` |
| `active` | `bg-surface` + `border-brand-solid` 테두리 + 안쪽 `bg-brand-solid` 점 | 뒤 구간 `bg-neutral-weak` |
| `pending` | `bg-surface` + `border-neutral-weak` 빈 원 | `bg-neutral-weak` |

<Canvas of={StepTrackStories.AllStates} />

가로 트랙은 라벨을 갖지 않으므로 **단독으로 쓰면 어느 단계인지 글자로 알 수 없다** — 항상 `StepHero`와 같이 놓는다.

<Canvas of={StepTrackStories.Hero} />

세로 트랙은 이름을 항상 표시하는 대신 설명을 활성 단계에만 붙인다. 이름 색은 `pending`만 `text-neutral-muted`이고 `done`·`active`는 둘 다 `text-neutral`라서, 완료와 현재는 이름이 아니라 노드 모양으로 구분된다.

## `multi` — 더블 매치위크 문구

`StepHero`와 `StepTrackVertical`만 `multi` prop을 받는다(가로 `StepTrack`은 노드만 그리므로 없다). `true`면 `STEP_META`의 `descMulti`로 갈아 끼우고, `descMulti`가 없는 스텝은 원래 `desc`로 폴백한다.

| 스텝 | `multi=false` | `multi=true` |
|---|---|---|
| `score` | 이번 주 경기 스코어를 예측해보세요 | 이번 주 두 경기의 스코어를 예측해보세요 |
| `pick` | 포지션별로 이번 주 활약할 선수를 골라보세요 | 포지션별로 각 경기에서 활약할 선수를 골라보세요 |
| `confirm` | 제출하기 전, 예측 내용을 확인해보세요 | (`descMulti` 없음 → 같은 문장) |

타이틀(`name`)은 `multi`와 무관하게 고정이다. 값은 `PredictionFlowClient`가 그 주의 경기 수로 계산한 `isMulti`를 그대로 내려준다.

## 배치

사용처는 `src/components/predict/PredictionFlowClient.tsx` 한 곳뿐이고, 같은 `step` 상태를 반응형 분기로 두 벌 그린다.

- `sm:hidden` — `<StepTrack current={step} />` + `<StepHero current={step} multi={isMulti} />`
- `hidden sm:block` — `<StepTrackVertical current={step} multi={isMulti} />`

바깥은 `sm:grid sm:grid-cols-[200px_1fr] sm:gap-x-10`이라 세로 트랙이 들어가는 칸은 **200px 고정폭**이다. 세로형 활성 설명의 `max-w-[168px]` 줄바꿈은 이 폭에서만 실제와 같아서 스토리도 200px로 감쌌다.

가로 트랙은 `w-1/2` — 부모 폭의 절반만 차지한다. 폭이 컴포넌트 안에 하드코딩돼 있으므로 좁은 칸에 넣으면 노드 간격이 그만큼 좁아진다.

## 쓰지 않을 때

스텝이 3개로 `STEP_META`에 하드코딩돼 있고 문구도 승부예측 전용이라, 다른 다단계 플로우에 재사용할 수 없다. 스텝 수·문구가 다른 화면이면 이 컴포넌트를 가져오지 말고 별도로 만든다. 노드에 `onClick`이 없어 단계 사이를 눌러 오가는 UI로도 쓸 수 없다.
