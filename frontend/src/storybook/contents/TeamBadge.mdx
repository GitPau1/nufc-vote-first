# TeamBadge

승부예측 화면의 팀 엠블럼 한 칸. `src/components/composition/predict/shared.tsx`에 있고, 승부예측 안에서만 쓰인다.
`logoUrl` / `name` / `size`(기본 48) / `grayscale`(기본 false) 네 개만 받는 표시 전용 컴포넌트다 — 팀 ID를 모르고, URL을 만들지도 않는다.

<Canvas of={TeamBadgeStories.Default} />

## 로고 URL은 이 컴포넌트가 만들지 않는다

주소는 `lib/predictions/week.ts`의 `teamLogoUrl(teamId)`이 조립한다.

```ts
`${SUPABASE_URL}/storage/v1/object/public/player-photos/team-logos/${teamId}.png`
```

엠블럼 파일은 public `player-photos` 버킷의 `team-logos/`에 FotMob 팀 ID를 파일명으로 올려둔다 — fixtures가 FotMob 동기화 데이터라 팀 ID가 곧 파일명이고, 별도 로고 테이블/매핑이 없다. 그래서 **팀 ID → URL 변환은 항상 호출하는 쪽 책임**이다. mock 모드(`NEXT_PUBLIC_SUPABASE_URL` 없음)에서는 `teamLogoUrl`이 `null`을 내므로 아래 1번 폴백으로 떨어진다.

| 만드는 곳 | 넘기는 값 |
|---|---|
| `lib/predictions/week.ts` (`groupFixturesByWeek`) | `MatchView.opponentLogoUrl`에 미리 담아 내려보낸다 |
| `components/composition/predict/PredictListClient.tsx` | 우리 팀 로고는 `teamLogoUrl(NUFC_TEAM_ID)`을 `MatchWeekList`의 `homeTeamLogoUrl` prop으로 |
| `PredictionFlowClient` / `PredictionResult` / `PredictionDone` | 렌더 시점에 `teamLogoUrl(NUFC_TEAM_ID)`, `teamLogoUrl(match.opponentId)`를 직접 호출 |

## 폴백 — 이 컴포넌트의 존재 이유

<Canvas of={TeamBadgeStories.NoLogo} />
<Canvas of={TeamBadgeStories.LoadFailed} />

폴백으로 떨어지는 경로가 둘이고 **결과는 같다**(`bg-disabled` 원 + 팀명 첫 글자).

1. `logoUrl`이 없음 — `MatchWeekList`의 `opponentLogoUrl`·`homeTeamLogoUrl`이 optional이라 실제로 도달한다.
2. `logoUrl`은 있는데 **로드 실패** — `onError`에서 내부 `failed` 상태를 세운다. 버킷에 그 팀 ID의 파일이 없으면(새 상대 팀 동기화 직후) Storage가 400을 주므로 여기로 온다.

2번이 없으면 깨진 이미지 아이콘이 그대로 남는다. 새 상대 팀·컵 대회 하위 리그 팀에서 실제로 나는 경우라, 스토리에서도 해석되지 않는 호스트(`.invalid`)로 이 경로를 강제로 보여준다.

폴백 원은 `aria-hidden`이라 **첫 글자가 스크린리더에 읽히지 않는다.** 실사용처 전부가 배지 바로 아래에 팀 이름 텍스트를 두고 있어서 그렇게 설계된 것이다 — 이름 없이 배지만 두는 자리에는 쓰지 않는다.

## grayscale — 끝난 경기 표시

<Canvas of={TeamBadgeStories.Grayscale} />

`grayscale`은 `filter: grayscale`(Tailwind `grayscale`) 한 줄이고, 판정 단위는 **경기**다 —
`MatchWeekList`가 `match.finished`를 그대로 내려준다. 한 주차에 끝난 경기와 안 끝난 경기가 섞이면
로고 톤도 경기마다 갈린다.

<Canvas of={TeamBadgeStories.GrayscaleFallback} />

폴백 경로에도 같은 클래스가 붙지만 **눈에 보이는 변화는 없다** — 폴백 원은 `bg-disabled`(#e9e9ea) +
`text-neutral-muted`(#666666)로 이미 무채색이라 채도를 뺄 게 없다. 위 스토리는 효과를 보여주는 게
아니라 prop을 넘겨도 폴백이 깨지지 않는다는 확인용이다. 즉 **끝난 경기라는 신호는 로고가 뜬 경우에만
로고 톤으로 전달된다** — 폴백으로 떨어진 팀은 톤이 같으므로, 그 신호가 꼭 필요한 자리면 배지 밖(점수·라벨)에서
따로 표시해야 한다.

## 알려진 제약

- **`MatchdayHero`에 같은 이름의 다른 구현이 있다.** `components/composition/predict/MatchdayHero.tsx:70`의 로컬 `TeamBadge`는 `id`/`name`/`align`을 받고 URL은 이제 같은 `teamLogoUrl`을 쓴다(로컬 `crestUrl`은 제거됨). 크기는 `h-11 w-11` 고정이고 **`onError` 폴백이 없어서 로드 실패 시 깨진 이미지가 남는다**(URL이 `null`인 mock 모드에서는 아무것도 그리지 않는다). 이름만 같은 별개 컴포넌트이므로 [MatchdayHero](?path=/docs/composition-predict-matchdayhero--docs)를 고칠 때 이 문서의 동작을 가정하면 안 된다.
- **같은 파일의 [PlayerPhoto](?path=/docs/composition-predict-playerphoto--docs)는 [Avatar](?path=/docs/primitives-avatar--docs)로 옮겼는데 이쪽은 아직 생 `<img>` + 직접 `onError`다.** 그대로 옮길 수 없어서다 — `Avatar` 루트가 `rounded-pill overflow-hidden`이라 세로/가로가 긴 엠블럼이 원형으로 잘린다. 지금은 `object-contain`으로 비율을 유지한다.
- 폴백 글자 크기는 `text-label-1-normal` 고정이라 `size`를 키워도 함께 커지지 않는다(위 Sizes 참고).
- `next/image`가 아니라 `<img>`를 직접 쓴다(`alt=""`, eslint-disable 주석 포함). `next.config.mjs`의 `remotePatterns`에 `*.supabase.co`가 있긴 하지만 앱 전체가 `next/image`를 쓰지 않아 그 설정은 지금 아무 영향이 없다.
- 폴백 마크업 중복은 정리됐다 — 예측 화면 세 곳이 복제하던 실루엣 원은 모두 `<PlayerPhoto url={null} size={40} />`로 모였고, `Silhouette`은 `PlayerPhoto` 폴백 전용이 됐다. 남은 중복은 위의 `MatchdayHero` 로컬 `TeamBadge` 하나뿐이다.
