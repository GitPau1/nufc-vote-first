# PollHomeSection

홈(`/`)의 "진행 중인 투표 / 예정된 투표 / 종료된 투표" 섹션 하나를 그리는 컴포넌트. 소스는 `src/components/polls/PollHomeSection.tsx`이고, `src/components/polls/HomeClient.tsx`(← `src/app/page.tsx`)에서 세 번 재사용된다. 카드 자체는 [PollCard](?path=/docs/contents-pollcard--docs)를 그대로 쓰고, 이 컴포넌트가 담당하는 건 **제목 줄 + 목록을 몇 개까지 어떤 배치로 보여줄지**다.

props는 `title`, `polls`, `action?` 셋뿐이다. 정렬·필터는 이미 `getPollHomeSections`(`lib/queries/polls.ts`)에서 끝난 상태로 넘어온다.

## 모바일 / 데스크탑 배치

같은 목록을 두 번 렌더해두고 `sm`(640px) 브레이크포인트로 하나만 보여준다 — `/polls`의 PollListClient와 같은 방식.

| | 모바일 (`<640px`) | 데스크탑 (≥640px) |
|---|---|---|
| 배치 | 세로 리스트, 카드 사이 `divide-y`, 전체를 surface 카드로 감쌈 | 그리드 (≥640px 2단, ≥1024px 3단) |
| PollCard variant | `horizontal` | `vertical` |
| 더 보는 방법 | "더보기" 버튼으로 3개씩 추가 | 좌우 버튼으로 페이지 넘김, 한 페이지 = 딱 한 줄 |

<Canvas of={PollHomeSectionStories.Mobile} />
<Canvas of={PollHomeSectionStories.TabletTwoColumn} />

데스크탑은 캐러셀(가로 스크롤)이 아니다. 열 수를 `window.matchMedia('(min-width: 1024px)')`로 직접 읽어 페이지당 개수를 결정하기 때문에, 브레이크포인트 값(1024px)이 tailwind의 `lg`와 어긋나면 한 줄에 3개인데 페이지는 2개씩 넘어가는 식으로 깨진다 — 둘을 같이 고쳐야 한다. 리사이즈로 열 수가 바뀌어 현재 페이지가 범위를 벗어나면 상태를 건드리지 않고 렌더링에서만 clamp한다.

## 언제 쓰고 언제 쓰지 않는지

- 홈처럼 **미리보기 한 줄**만 보여주고 전체는 다른 화면으로 넘길 때 쓴다.
- 탭 전환·무한 스크롤이 필요한 전체 목록 화면에는 쓰지 않는다. 그건 `/polls`의 `PollListClient`다.
- `action`은 "그 섹션 전체를 볼 수 있는 화면이 따로 있을 때"만 준다. 홈에서 실제로 붙은 곳은 종료된 투표 섹션(→ `/polls`) 하나뿐이다.

## 빈 목록은 섹션째로 사라진다

`polls`가 빈 배열이면 `null`을 반환한다 — 빈 상태 문구도, 제목도 남지 않는다. 그래서 "투표가 하나도 없습니다" 같은 안내는 이 컴포넌트가 아니라 호출부(`HomeClient`)가 세 섹션이 모두 비었을 때 직접 그린다. 섹션 안에 빈 상태 메시지를 넣고 싶으면 이 컴포넌트를 고쳐야 한다.
