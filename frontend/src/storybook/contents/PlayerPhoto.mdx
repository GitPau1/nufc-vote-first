# PlayerPhoto

승부예측에서 선수 사진이 들어가는 원형 자리. `src/components/composition/predict/shared.tsx`에 있고 `url`(nullable)과 `size`(기본 64)만 받는다.
[Avatar](?path=/docs/primitives-avatar--docs) 위에 얹은 **선수 사진 전용 래퍼**다 — 폴백이 이니셜이 아니라 실루엣이라는 것 하나가 차이의 전부다.

<Canvas of={PlayerPhotoStories.NoPhoto} />

`url`이 null인 경우도, URL은 있으나 요청이 실패한 경우도 실루엣 폴백으로 수렴한다. 두 스토리 결과가 같아야 정상이다. `url`이 null이면 `AvatarImage`를 아예 렌더하지 않고, URL이 있으면 렌더한 뒤 실패 시 Radix가 fallback으로 바꾼다.

## 사용자 프로필 아바타와 뭐가 다른가

같은 `primitives/avatar.tsx` 프리미티브를 쓰지만 **폴백이 다르다.**

| | 폴백 | 쓰는 곳 |
|---|---|---|
| 사용자 프로필 | 이름 **이니셜** (`bg-brand-weak`/`bg-disabled`) | `components/composition/common/UserMenu.tsx`, `components/composition/my/MyPageClient.tsx`, `components/composition/polls/CommentsSection.tsx` |
| `PlayerPhoto` | **실루엣 아이콘** (`bg-disabled`) | 승부예측 화면 (아래 표) |

선수 자리는 사진 옆·아래에 이름이 이미 붙어 있어서 이니셜이 정보를 더하지 않는다. 반대로 사용자 아바타는 목록에서 단독으로 서는 경우가 있어 이니셜이 식별에 쓰인다. 새 자리를 만들 때 이 기준으로 고른다 — 이름이 옆에 있으면 실루엣, 아바타만 서면 이니셜.

## 사진 URL은 이 컴포넌트가 만들지 않는다

`lib/predictions/candidates.ts`의 `playerPhotoUrl(fotmobPlayerId)`이 조립한다.

```ts
`${SUPABASE_URL}/storage/v1/object/public/player-photos/players/${fotmobPlayerId}.png`
```

사진 파일은 public `player-photos` 버킷의 `players/`에 `fotmob_player_id`를 파일명으로 올려둔다(현재 시즌 스쿼드 25명 전원). `Candidate.photoUrl`에 담겨 내려오고, 없으면 `null`이다 — mock 모드(`NEXT_PUBLIC_SUPABASE_URL` 없음)에서도 `null`이다. 버킷에 없는 id는 Storage가 **400**을 주므로, 스토리에서는 다른 예측 mock과 같은 `placehold.co`를 쓴다(스토리 파일 주석에도 같은 이유를 적어뒀다).

## 사용처와 size

| 파일 | 자리 | size |
|---|---|---|
| `components/primitives/modal/contents/PlayerPick.tsx:132` | 선수 선택 목록의 행 | 기본(64) |
| `components/composition/predict/PredictionFlowClient.tsx:474` | 선수 선택 단계의 선택된 카드 | 기본(64) |
| `components/composition/predict/PredictionResult.tsx:395` | 결과 화면 포지션별 카드 | 기본(64) |
| `components/composition/predict/PredictionResult.tsx:368` | 결과 요약 줄 | 48 |
| `components/composition/predict/PredictionDone.tsx:260` | 제출 완료 화면 카드 | 기본(64) |
| `components/composition/predict/PredictionDone.tsx:235` | 제출 완료 요약 줄 | 48 |

실제로 쓰이는 값은 40·48·64 세 개다. `size`는 `Avatar` 기본 `h-10 w-10`을 인라인 `style`로 덮어쓰는 방식이라 임의 px이 그대로 들어간다.

**"선수를 아직/아예 선택하지 않음"을 그리는 자리도 이 컴포넌트다** — `url={null} size={40}`. `Silhouette`은 이 컴포넌트의 폴백 전용이니 직접 감싸 쓰지 않는다.

## 알려진 제약

- **실루엣 아이콘은 20×20 고정이다.** `Silhouette`이 SVG의 `width`/`height`를 하드코딩해서, `size`를 키우면 원만 커지고 아이콘은 그대로 작게 남는다(위 Sizes 참고). 40/48/64에서는 문제 없지만 큰 자리에 쓰기 전에 확인할 것.
- `alt=""`(장식)이다. 선수 이름은 항상 사진 바로 옆·아래 텍스트로 읽히는 걸 전제한다.
- `next/image`가 아니라 Radix의 `<img>`다. `next.config.mjs`의 `remotePatterns`에 `*.supabase.co`가 있긴 하지만 앱 전체가 `next/image`를 쓰지 않아 그 설정은 지금 아무 영향이 없다.
