# WeekRankCard

승부예측 **한 주차** 랭킹 카드. `src/components/composition/predict/WeekRankCard.tsx`이고, 사용처는 `components/composition/predict/PredictionResult.tsx`의 피날레(다크 카드, 결과 화면 맨 아래) 하나다. 데이터는 `lib/queries/predictions.ts`의 `getWeekRanking(weekKey)`가 `week_leaderboard` view에서 읽은 `RankingRow[]`를 그대로 받는다.

받은 값을 그리기만 한다 — 순위·점수를 계산하지 않는다. 유일한 자체 상태는 "더보기"로 펼쳤는지(`expanded`)뿐이다.

<Canvas of={WeekRankCardStories.Mobile} />

## [RankingCard](?path=/docs/composition-predict-rankingcard--docs)와 무엇이 다른가

이름이 비슷하고 행 모양도 닮았지만 **다른 카드다.** 둘을 헷갈리면 컬럼과 데이터가 어긋난다.

| | WeekRankCard | [RankingCard](?path=/docs/composition-predict-rankingcard--docs) |
|---|---|---|
| 범위 | 한 주차 랭킹 | 시즌 누적 랭킹 |
| 점수 컬럼 | **예측 / 선수픽 / 종합** 3개 | 종합(총점) 1개, `N점` 표기 |
| 인원 | 참여자 전체(펼쳐볼 수 있다) | `entries.slice(0, limit)` 고정 |
| 자르기 | 10명(`DESKTOP_CAP`) + "더보기" — 폭 구분 없음 | 없음 |
| variant | 없다(카드 하나) | `top3` / `mine` 2종 |
| 순위 변동 | 없다 | `delta`로 ▲▼ 표기 |
| 쓰이는 곳 | `PredictionResult.tsx` 피날레(다크 카드) | `PredictListClient.tsx`(예측 목록 데스크탑 사이드) |
| 데이터 | `getWeekRanking()` — 실 데이터 연결됨 | 쿼리 없음(프리뷰 하드코딩) |
| 색 팔레트 | 온솔리드 계열(다크 면 전용, `text-on-solid*`) | 라이트 팔레트(`text-neutral*`) |
| 렌더 | `'use client'`(펼침 상태를 들고 있다) | 상태 없는 프레젠테이션 |

행의 React key도 다르다 — 여기는 `entry.userId`, RankingCard는 `entry.rank`다. 그래서 동점(공동 순위)이 이 카드에서는 안전하고 RankingCard에서는 key 중복이 된다.

## 자르는 방식은 폭과 무관하게 하나뿐이다 (2026-09-01 개편)

과거에는 `capped` prop으로 데스크탑(10명 캡+버튼)과 모바일(전체 렌더+`max-h-[46vh]` 페이드)이 서로 다른 방식을 썼다. "판정 퍼스트" 결과 화면 개편으로 모바일/데스크탑 레이아웃 자체가 같아지면서 이 prop을 없앴다 — 지금은 폭과 무관하게 10명(`DESKTOP_CAP`)까지만 그리고 "더보기 ▾"로 나머지를 편다.

<Canvas of={WeekRankCardStories.Desktop} />

| | 폰 폭(`Mobile`) | 데스크탑 폭(`Desktop`) |
|---|---|---|
| 로직 | 동일 — `DESKTOP_CAP=10` + 더보기 | 동일 |
| 잘린 행 | DOM에 없다(캡을 넘는 행 자체를 안 만든다) | 동일 |
| 내 순위가 밖일 때 | `⋯` 뒤에 내 행을 따로 붙인다 | 동일 |

두 스토리의 유일한 차이는 감싸는 컨테이너 폭(데코레이터)뿐이다 — 컴포넌트 자체는 `className`으로 받은 폭에 맞춰 늘어나거나 줄어든다.

<Canvas of={WeekRankCardStories.MyRankBelowCap} />

`⋯` + 내 행 보강은 캡을 넘겼을 때만 나온다. 붙인 행의 순위 숫자는 실제 순위(14) 그대로다(11위처럼 보이면 안 된다).

## 펼침은 한 방향

<Canvas of={WeekRankCardStories.MobileExpanded} />

"더보기 ▾"를 누르면 캡과 버튼이 한꺼번에 사라지고 전체 목록이 보인다. **접기는 없다** — 다시 접으려면 카드를 리마운트해야 한다.

<Canvas of={WeekRankCardStories.Expanded} />

펼친 뒤에는 `⋯`와 따로 붙였던 내 행도 없어지고, 내 행이 목록 안에 한 번만 남는다(펼침 분기가 `myRowBelow` 계산과 같은 조건을 공유하지 않으면 내 행이 두 번 나오는 회귀가 난다).

<Canvas of={WeekRankCardStories.FewParticipants} />

참여자가 10명 이하면 "더보기" 버튼 자체가 뜨지 않는다. 주차 초반에 실제로 보는 상태다.

## 내 행 강조

강조는 prop이 아니라 **`entry.isMe`**가 결정한다. 행 배경 `bg-on-solid-strong` + 순위·종합 숫자 `text-on-solid-brand`(다크 면 전용 강조 토큰, `--sem-fg-on-solid-brand` → 팔레트 `--p-blue-400`)이고, 배경이 깔린 행만 좌우 패딩이 `px-1 → px-2`로 늘고 상단 구분선이 빠진다.

<Canvas of={WeekRankCardStories.NoMyRow} />

`isMe`가 붙은 행이 없으면(미로그인·미참여) 강조도 `⋯` 보강도 전부 사라지고 목록만 남는다. 여기에 "너는 참여하지 않았다"는 안내는 없다 — RankingCard의 `mine` variant가 갖고 있는 미참여 문구에 해당하는 게 이 카드에는 없다.

## 점수 3컬럼과 비어 있는 상태

<Canvas of={WeekRankCardStories.MissingColumnPoints} />

`RankingRow`에서 `matchPoints`·`pickPoints`는 **주차 랭킹 전용 옵셔널**이다. 시즌 누적 행(`getSeasonRanking()`)에는 없고, 그런 행을 이 카드에 넘기면 빈칸이 아니라 `?? 0`으로 **0**이 찍혀 "0점을 받았다"처럼 읽힌다. 이 카드에는 `getWeekRanking()` 결과만 넘긴다.

점수 칸에 [Badge](?path=/docs/primitives-badge--docs)는 쓰지 않는다. 세 컬럼 모두 그냥 텍스트이고, 값에 따라 색이 바뀌는 tier도 없다 — 예측/선수픽은 `text-on-solid-muted`, 종합은 `text-on-solid-brand` 고정이다. 적중/근접 같은 tier 배지(`PointsBadge`·`RatingBadge`)는 같은 화면의 `PredictionResult.tsx`에 따로 있고, 이 카드와 공유하지 않는다.

<Canvas of={WeekRankCardStories.Empty} />

`entries`가 비면 컬럼 헤더조차 그리지 않고 "아직 이 주차에 채점된 예측이 없어요" 한 줄만 남는다. 채점 전 주차가 이 상태다.

<Canvas of={WeekRankCardStories.TiedRanks} />

동점 처리는 이 카드의 일이 아니라 view의 일이다 — 공동 2위 두 명 뒤 4위로 건너뛰는 것도 받은 값을 그대로 그린 결과다.

<Canvas of={WeekRankCardStories.LongNamesAndAvatars} />

`avatarUrl`이 없으면 `bg-on-solid-strong` 원 + `User` 아이콘으로 대체된다. 이름만 `truncate`로 줄고 순위(`w-8`)·점수 3컬럼(`w-[42px]`/`w-[42px]`/`w-12`)은 고정폭이라 긴 닉네임에 밀리지 않는다.

## 알려진 제약

- **종합 점수 컬럼에서 내 점수와 남의 점수가 색으로 구분되지 않는다.** 내 행과 남의 행의 종합 점수가 모두 `text-on-solid-brand`라, 내 행은 배경 + 순위 숫자로 식별되지만 **가장 오른쪽 숫자만 눈으로 훑을 때 내 점수를 못 짚는다.** 여기에 강조를 되살린다면 밝기 차가 아닌 다른 수단(굵기·배경·크기)을 새로 정해야 한다.
- "더보기" 버튼에는 hover 피드백이 없다(다크 면 위 저채도 텍스트 버튼이라 hover 스타일을 별도로 정의하지 않았다).
- 컬럼 헤더가 더 이상 `sticky`가 아니다(2026-09-01 개편 전에는 모바일 전용 스크롤 컨테이너 안에서 `sticky top-0`였는데, 그 스크롤 컨테이너 자체가 없어졌다) — 펼쳐서 길어져도 헤더는 페이지와 같이 스크롤된다.
- 셸을 [Card](?path=/docs/primitives-card--docs)로 만들지 않는다 — 결과 화면 피날레의 다크 카드(`spotlight-glow-brand-strong`) **안에** 투명하게 얹히는 패널이라 자체 배경·테두리가 없다(흰 표면 + 보더 셸인 RankingCard와 다른 지점). 그래서 색 토큰도 전부 `text-on-solid*`/`bg-on-solid-*` 계열이고, 라이트 면 토큰(`text-neutral*`, `bg-page`)을 쓰면 다크 배경 위에서 대비가 무너진다.
- 구분선은 새 토큰을 만들지 않고 기존 `--sem-bg-on-solid-weak`(원래 배경용, rgba(255,255,255,.05))를 `border-on-solid-weak`로 겸용한다 — 시안(8%)보다 살짝 연하다는 걸 인지하고 승인된 값이다.
