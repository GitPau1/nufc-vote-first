# Typography

폰트는 **Pretendard Variable**이다. 타입 스케일은 Wanted Design Library의 역할 기반 스케일을 그대로 쓴다 — 크기가 아니라 **역할**로 고른다.

크기와 굵기는 독립된 축이다. `text-body-1-normal`로 크기를 정하고 `font-bold`로 굵기를 따로 정한다.

**`1`/`2` 접미사는 화면 단위(데스크탑/모바일)를 뜻하는 경우가 많다** — 위계가 다른 별개의 역할이 아니라, **같은 역할을 어떤 화면 크기에서 쓰느냐**의 구분이다.
- `heading-1`(데스크탑) ↔ `heading-2`(모바일) — 둘 다 "섹션 제목" 역할, 화면 크기만 다르다.
- `headline-1`(데스크탑) ↔ `headline-2`(모바일) — 둘 다 "카드·모달 제목" 역할.
- Display·Title은 **연쇄적으로** 대응한다 — 한 단계 큰 화면(데스크탑)의 토큰이 한 단계 작은 화면(모바일)에서는 그다음 토큰으로 내려간다:

| 역할(크기 단계) | 데스크탑 | 모바일 |
|---|---|---|
| 최상위 히어로 | `display-1` | `title-1` |
| 그다음 단계 | `title-1` | `title-2` |
| 그다음 단계 | `title-2` | `title-3` |

그래서 `title-1`은 **이중 역할**이다 — 모바일에서는 `display-1`(데스크탑)과 같은 최상위 히어로, 데스크탑에서는 `title-2`(모바일)와 같은 한 단계 작은 역할이다. `title-2`도 마찬가지로 이중 역할.

## 고르는 순서

1. 이 텍스트의 **역할**이 무엇인가 — 제목인가, 본문인가, 라벨인가, 메타인가
2. 그 역할이 **데스크탑용인가 모바일용인가** — `heading-1`/`heading-2`, `headline-1`/`headline-2`, `display-1`/`title-1`처럼 같은 역할의 화면 단위별 짝이 있으면 그중에서 고른다
3. 여러 줄로 흐르는가? → `reading` 변형이 있으면 그걸 쓴다
4. 강조가 필요하면 **크기를 올리지 말고** `font-bold`를 쓴다

## 하지 말 것

- `text-[15px]`, `leading-[22px]`, `tracking-[-0.5px]` 같은 임의값을 만들지 않는다.
- Tailwind 기본 크기(`text-sm`, `text-lg` 등)를 쓰지 않는다 — 우리 스케일과 값이 다르다.
- 위 두 항목은 `design-foundation.test.mjs`가 막는다.
