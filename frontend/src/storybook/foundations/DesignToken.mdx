# Design Token

이 페이지는 **토큰 개별 값이 아니라 토큰 체계 자체의 구조**를 설명한다. "무슨 색을 쓸까"는 [Color](?path=/docs/foundations-color--docs)/[Semantic](?path=/docs/foundations-semantic--docs)/[Palette](?path=/docs/foundations-palette--docs)에 있고, 여기는 "그 토큰들이 왜 지금 모양으로 나뉘어 있는가"만 다룬다.

## 세 세대가 있었고, 지금은 하나다

`globals.css`/`tailwind.config.ts`에는 이름 짓는 방식이 다른 세 세대가 순서대로 쌓여 있었다. **색 토큰은 이제 ③ 하나만 남았다** — ①·②는 사용처를 옮기고 정의까지 지웠다.

| 세대 | 예 | 지금 상태 |
|---|---|---|
| ① LDSG 이전 세대 — flat hex | `--c-primary`, `--c-gray-1~4`, `--c-bg`, `--c-surface` | **색 토큰 전부 삭제.** `--c-black` 하나와 radius·shadow(`--r-*`, `--sh-*`)만 남았다 |
| ② shadcn/ui 세대 — HSL 변수 | `--background`, `--foreground`, `--border`, `--muted-foreground`, `--primary`, `--secondary`, `--card`, `--ring` | **전부 삭제.** `tailwind.config.ts`의 `colors` 블록이 사실상 비었다 |
| ③ Palette → Semantic 2계층 | `--p-blue-700`(원시) → `--sem-bg-brand-solid: var(--p-blue-700)`(역할) | **유일한 색 계층.** 새 코드도 기존 코드도 이 계층만 참조한다 |

③은 리서치 문서(`디자인시스템-리서치-몽타주-시드디자인.md` §1.2)에서 확인한 Montage의 atomic→semantic 구조와 같은 모양이다 — 원시 팔레트(`--p-*`)는 화면에 직접 안 쓰고, 역할 이름(`--sem-*`)만 컴포넌트가 참조한다.

## 어느 쪽이 신버전인가 — git이 답한다

이름만 보면 `bg-background`(②)가 익숙하고 `bg-page`(③)가 낯설어서 세대를 거꾸로 짚기 쉽다. 실제 순서는 이렇다.

| 커밋 | 무엇이 들어왔나 | `origin/main`에 있나 |
|---|---|---|
| `a72b7b8` "파일 구조 이동 및 이름 변경" | `--c-*` flat hex, shadcn HSL 변수 | **있다** |
| `4602c15` "디자인시스템 Storybook 구축…" | `--p-*` 팔레트, `--sem-*` 전체 | **없다** |

즉 **`--sem-*`가 신버전, `--c-*`·shadcn HSL이 구버전이다.** 승부예측 화면이 옛 하늘색으로 튀었던 것도 같은 이유다 — main에서 병합돼 들어온 코드라 구버전 토큰을 쓰고 있었다. 세대를 판단할 때 이름의 익숙함이 아니라 이 표를 본다.

## 무엇을 어디로 옮겼나

| 구버전 | → 신버전 | 값 변화 |
|---|---|---|
| `bg-background` | `bg-page` | #fafafa → #fafafb |
| `text-foreground`, `text-card-foreground` | `text-neutral` | #111111 → #1a1b1c |
| `text-muted-foreground` | `text-neutral-muted` | 없음(아래 참고) |
| `text-secondary-foreground` | `text-neutral-strong` | #333333 → #313335 |
| `border-border`, `border-input` | `border-neutral-weak` | #e1e7ef → #e9e9ea |
| `bg-border`(구분선 채우기) | `bg-neutral-weak` | 같은 값 |
| `bg-secondary`, `bg-muted` | `bg-disabled` | #ebebeb → #e9e9ea |
| `ring-ring`(포커스 링) | `ring-brand-solid` | #41b6e6 → #115aff |
| `bg-primary`, `text-primary`, `text-primary-dark` | `bg-brand-solid`, `text-brand` | #41b6e6 → #115aff |
| `bg-primary-dim` | `bg-brand-weak` | rgba(65,182,230,.12) → #d8f1ff |
| `text-gray-1~3` | `text-neutral-strong` / `text-neutral-muted` / `text-neutral-subtle` | 역할에 따라 |
| `bg-surface` | **이름 유지**, 값만 `--sem-bg-surface`로 | 없음 |
| `--accent*`, `--popover*`, `--destructive*`, `--radius` | 대체 없이 삭제 | 실사용 0건이었다 |

`text-neutral-muted`만 예외적으로 **팔레트 단계가 아니라 손으로 맞춘 `#666666`**이다. 팔레트 단계(neutral-700 `#6e7277`)를 그대로 쓰면 이 토큰이 실제로 얹히는 옅은 틴트 배경 위에서 AA가 무너진다 — `bg-disabled` 3.99:1, `bg-brand-weak` 4.14:1, `bg-critical-weak` 4.12:1. `primitives/badge.tsx`의 `outline` variant처럼 앱 전반에서 쓰이는 조합이라, **이름만 ③으로 옮기고 검증된 값은 유지**했다. [Palette](?path=/docs/foundations-palette--docs)의 `-weak` 배경 6종이 같은 이유로 손으로 맞춘 값인 것과 같은 처리다.

`--c-black`만 ①에 남는다 — 이미지 위 스크림(`from-black/35`)이 `/알파` 수정자를 쓰려면 rgb 채널값 형태가 필요하고 대응하는 sem 토큰이 아직 없다. `.animate-skeleton`·`.spotlight-glow-brand`는 `--c-disabled`·`--c-bg` 대신 `--sem-bg-disabled`·`--sem-bg-page`를 직접 참조하도록 바꿔서 ① 의존을 끊었다.

## 새 코드는 ③만 쓴다

`bg-brand-solid`, `text-neutral-strong`, `border-critical-weak`처럼 **`sem-` 접두사 CSS 변수를 노출하는 Tailwind 클래스만** 쓴다. 이제 다른 선택지가 아예 없다 — 옛 이름들은 정의가 없어서 Tailwind가 클래스를 만들지 않는다. 다만 **알 수 없는 클래스는 에러 없이 조용히 무시된다**는 점이 함정이라, `design-foundation.test.mjs`가 두 방향을 함께 고정한다.

| 검사 | 무엇을 막나 |
|---|---|
| `retired legacy color tokens stay deleted` | 지운 CSS 변수·`colors` 항목이 되살아나는 것 |
| `retired legacy color class names are gone repo-wide` | 소스·문서에 옛 클래스명이 남거나 새로 들어오는 것 |

`colors` 블록에는 `black` 하나만 허용된다는 것까지 검사가 못 박아 뒀다 — 색은 역할별 블록(`backgroundColor`/`textColor`/`borderColor`/`ringColor`)에서만 정의한다.

## 이름이 겹치던 함정 — `primary`는 없앴다

한동안 ①과 ②가 동시에 `primary`라는 이름을 썼다. `--c-primary`(①, 옛 브랜드색 `#41b6e6`)와 `--primary`(②, shadcn HSL, 같은 옛 색)가 둘 다 살아 있어서 `tailwind.config.ts`가 `bg-primary`/`text-primary`/`bg-primary-dark`를 전부 유효한 클래스로 노출했고, **임의값이 아니라서 `design-foundation.test.mjs`도 못 잡았다.** 이름만 보고 "brand니까 primary겠지"라고 고르면 화면에 새 브랜드 파랑(`#115aff`)이 아니라 폐기된 옛 파랑(`#41b6e6`)이 나오는 함정이었다 — [Gradient](?path=/docs/foundations-gradient--docs) 문서를 쓰다가 걸린 사용처(`TypeBPollClient.tsx`의 그라디언트)를 하나 찾아 고쳤고, 승부예측 화면 전체가 같은 함정에 빠진 상태로 main에서 들어왔다.

**지금은 세 정의를 다 지웠다.** `bg-primary`·`text-primary`·`bg-primary-dim`·`text-primary-dark`는 존재하지 않는 클래스이므로 실수로 고를 수 없다. 브랜드색으로 가는 길은 `bg-brand-solid`/`text-brand`/`bg-brand-weak`/`border-brand-solid` 하나뿐이다.

같은 이유로 포커스 링도 정리했다 — `ring-brand-solid`(shadcn 기본, `primitives/button.tsx`·`primitives/badge.tsx`의 `focus-visible`)이 `--ring`을 통해 옛 하늘색을 가리키고 있어서, 앱이 전부 brand로 넘어간 뒤에도 **포커스 링만 구세대 색으로 남아 있었다.** 클래스 이름은 그대로 두고 `ringColor.ring`이 `--sem-stroke-focus-ring`을 가리키게 바꿨다.

**규칙: 색을 고를 때는 이름이 그럴듯해 보여도 항상 [Color](?path=/docs/foundations-color--docs)/[Semantic](?path=/docs/foundations-semantic--docs) 표에서 먼저 확인하고 고른다.** `tailwind.config.ts`나 `globals.css`에 정의돼 있다는 사실 자체가 "지금 써도 되는 토큰"이라는 뜻이 아니다.

## 새 토큰이 필요할 때

먼저 [Palette](?path=/docs/foundations-palette--docs)에 있는 색 계열 안에서 되는지 본다. 안 되면 팔레트를 늘릴지, 기존 semantic 토큰을 재사용할지 먼저 논의한다 — 판단 없이 새 hex를 추가하지 않는다.

## 하지 말 것

- 지운 토큰을 되살리지 않는다. "shadcn 컴포넌트를 새로 붙이는데 `--primary`가 필요하다" 같은 상황이 오면, 그 컴포넌트를 ③ 토큰으로 고쳐 쓴다 — `primitives/button.tsx`·`primitives/badge.tsx`·`primitives/card.tsx`가 이미 그렇게 돼 있다.
- `colors` 블록에 색을 추가하지 않는다. 거기에 넣으면 `bg-`/`text-`/`border-`/`ring-`/`fill-`에 한꺼번에 퍼져서, 역할과 무관한 조합까지 "정의된 토큰"처럼 보이게 된다. 역할별 블록에 넣는다.
- 세대를 이름의 익숙함으로 판단하지 않는다 — 위 git 표를 본다.
- 이 페이지에 개별 토큰 값·용도를 옮겨 적지 않는다. 그건 [Color](?path=/docs/foundations-color--docs)/[Semantic](?path=/docs/foundations-semantic--docs)/[Palette](?path=/docs/foundations-palette--docs)의 몫이고, 복사본은 원본보다 먼저 낡는다.
