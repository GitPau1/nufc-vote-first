# Gradient

**예외적으로만 쓴다.** 대부분의 화면은 [Color](?path=/docs/foundations-color--docs)의 solid 값으로 충분하다. 아래 표가 이 문서가 다루는 전부고, 전부 "여러 색을 섞어 꾸미는" 용도가 아니라 **한 가지 실용적인 문제**(스크롤 시 헤더 경계, 사진 없을 때 배경, 사진 위 텍스트 가독성, 어두운 카드에 밋밋하지 않은 포인트, 대회별 색 구분, 최고 평점 카드의 트로피 강조)를 풀기 위한 것이다. 준비만 해두고 안 쓰는 그라디언트 유틸리티는 이제 없다 — `competition-*` 9종(대회색 다크 글로우·라이트 wash·배지)도 대회별 색 구분이라는 실사용처를 위해 추가됐다. 새 화면에 그라디언트가 필요해 보이면 먼저 flat color로 되는지 확인한다.

표 밖에 남는 그라디언트는 셋이다: 로딩 뼈대의 shimmer(`.animate-skeleton`, 색보다 애니메이션이 핵심이라 [Motion](?path=/docs/foundations-motion--docs)에서 다룬다), 캐러셀 사진 아래쪽 스크림(`bg-gradient-to-t from-black/35`, `TypeBPollClient.tsx:211`), 주차 랭킹 목록이 잘릴 때 "더 있음"을 암시하는 하단 페이드(`after:bg-gradient-to-b after:to-surface`, `WeekRankCard.tsx:55`). 뒤의 둘은 한 곳에서만 쓰는 인라인 유틸리티라 클래스로 뽑지 않았다.

## 다크 변형 — `spotlight-glow-brand-strong`

```css
.spotlight-glow-brand-strong {
  background:
    radial-gradient(250px at 0% 0%, color-mix(in srgb, var(--p-blue-700) 15%, transparent) 0%, transparent 70%),
    radial-gradient(250px at 100% 0%, color-mix(in srgb, var(--p-blue-600) 15%, transparent) 0%, transparent 70%),
    var(--sem-bg-neutral-strong);
}
```

베이스가 `bg-neutral-strong`(어두운 중립 배경, Pick One 카드와 같은 색)이고, **라이트 쪽(`spotlight-glow-brand`)이 대각 linear로 바뀐 뒤에도 이쪽은 원래의 코너 radial 방식(`250px at 0% 0%` / `at 100% 0%`, 2단 스톱)을 그대로 쓴다.** `MatchdayHero.tsx:178`(홈 히어로)에 적용됨. 히어로 카드는 높이가 충분해서 라이트에서 문제가 됐던 "반경 > 카드 높이"에 걸리지 않고, 높이가 데이터에 따라 널뛰지도 않아 절대 px 반경이 실제로 문제를 일으키지 않는다.

**기하 자체가 다르다.** 라이트(`spotlight-glow-brand`)는 **135deg 대각 linear 한 겹**(8%, 55%에서 소멸)이고 다크(`-strong`)는 **코너 radial 2겹**이다. 이름이 `-strong` 접미사로 쌍처럼 보이지만 두 클래스는 같은 기법의 밝기 변형이 **아니다**.

**계수도 서로에서 파생된 값이 아니다.** 다크 15%는 라이트가 20%였을 때 그 값을 낮춰 정한 것이었지만, 라이트가 2026-08-25에 코너 12% → 블롭 15%/14% → 세로 linear 8% → (2026-09-05) 135deg 대각 8%로 여러 번 바뀌면서 그 관계가 완전히 끊겼다. 지금 두 값은 각 베이스 위에서 독립적으로 정해진 것이므로, 한쪽을 고칠 때 다른 쪽을 따라 맞추지 않는다.

**베이스도 서로 무관하다.** 라이트가 `bg-page` → `bg-surface`로 바뀐 것은 그 카드가 놓이는 페이지 배경과 색이 겹쳐서였고, 다크의 `bg-neutral-strong`은 그 사정과 관계가 없어 그대로다.

**색 구성도 갈린다.** 라이트는 `blue-700` **1색**이고, 다크는 `blue-700` + `blue-600` **브랜드 blue 2단계**다(둘 다 브랜드 blue라는 점만 같다). 두 클래스는 이제 이름과 용도만 짝을 이루고 기하·계수·베이스·색 구성이 전부 각각이다 — 한쪽을 보고 다른 쪽 값을 추측하지 않는다.

이 앱은 다크모드 자체가 없어서(라이트 테마 전용, Color.mdx 참고) `text-positive` 같은 상태 색 텍스트는 라이트 배경 기준으로 대비가 맞춰져 있다 — 이 다크 카드 안에서는 그 토큰들을 그대로 쓰지 않고, 이미 `bg-neutral-strong` 카드(`PlayersPageClient.tsx`의 Pick One 카드)가 쓰는 `text-white`(주요 텍스트) / `text-disabled`(보조 텍스트) 조합을 그대로 재사용한다.

로딩 중 뼈대(skeleton)의 shimmer 그라디언트(`.animate-skeleton`)는 색 자체보다 애니메이션이 핵심이라 [Motion](?path=/docs/foundations-motion--docs)에서 다룬다.

`color-mix()`는 Chrome 111+ / Safari 16.2+ / Firefox 113+에서만 동작한다. 이 표의 `-strong`·`competition-*` 글로우/워시 전부 `color-mix()`를 쓰므로, 이 프로젝트가 지원하는 브라우저 범위에서 문제없는지는 실제로 화면에 쓰기 전에 한 번 더 확인한다.

## 하지 말 것

- 새 그라디언트를 임의 hex로 만들지 않는다. 위 목록 중 하나를 재사용할 수 없는지 먼저 확인하고, 안 되면 새로 만들기 전에 논의한다.
- flat color(Color.mdx)로 되는 화면에 강조 목적으로 그라디언트를 얹지 않는다.
- 새 그라디언트에도 폐기된 색 이름(`primary`/`primary-dark`/`negative`/`positive-dim` 등)을 쓰지 않는다 — semantic 이름(`brand-solid` 등)만 쓴다.
